# SpaceWatch 최종 통합 프로그램

360도 영상의 전처리·복원·의미 메시, 관측 후보와 키프레임 선정, 회차 정합,
원본 RGB 변화비교, 최종 뷰어를 연결한 제출용 프로그램이다. Gaussian은 사용하지 않는다.
사람 설문 응답·설문 분석은 포함하지 않는다.

## 1. 다른 컴퓨터에서 결과 화면 열기

GitHub 저장소의 `통합파일` 폴더(압축 배포에서는 `SpaceWatch_Final`)에서 다음을 실행한다. Python 3.10 이상이면 되고,
추가 패키지·GPU·모델·서버 접속은 필요 없다.

```bash
python3 demo.py --port 8766
```

브라우저에서 `http://127.0.0.1:8766/pipeline.html?capture=dorm5#tour`를 연다.
종료는 실행한 터미널에서 Ctrl+C이다. 지도 회전·우클릭 이동·휠 확대, 키프레임 이동,
W/A/S/D 시선 회전, 변화 후보 근거와 표시 켜기/끄기를 사용할 수 있다.

결과 화면에는 **Dorm5의 현재 선정 10지점**과 원본 화질의 실제 ERP 10장,
필요한 RGB/의미 지도, 현재 변화 근거 사진만 포함했다. 원본 사진을 축소하거나
재인코딩하지 않았다. 중간 이동 프레임, 원본 점군, 대형 모델, Dorm4 화면은 넣지 않았다.
이것은 완료된 계산 결과를 표시하는 데모이며, 데모 실행을 새 추론이라고 표시하지 않는다.

## 2. 전체 파이프라인 실행

계산 프로그램의 진입점은 `code/spacewatch.py`이다. 데모와 달리 전체 계산은 학교 서버의
기존 모델·런타임·대형 입력을 사용한다. 이 압축파일만으로 다른 컴퓨터에서 전체 모델을
계산할 수 있다는 뜻은 아니다. 정확한 외부 의존 경로는 `evidence/EXTERNAL_DEPENDENCIES.json`,
세부 생성기와 사용법은 `code/README.md`를 따른다.

서버 배포 경로:
`/workspace/spacewatch_integrated_20261110_8QJn4J/final_release_v1`

```bash
cd /workspace/spacewatch_integrated_20261110_8QJn4J/final_release_v1/code
python3 spacewatch.py --version
python3 spacewatch.py doctor --config configs/dorm45-paper.json

# 기존 복원·의미 입력의 출처와 해시를 확인한 후, 후보·관측 행렬부터 새 계산
python3 spacewatch.py start --config configs/dorm45-paper.json --output ../runs/new_run
python3 spacewatch.py status --output ../runs/new_run

# 원래 영상 준비 생성기부터 전체 계산: 메모리 안전 조건 충족 시에만 실행
python3 spacewatch.py run-fresh --request requests/dorm45-fresh.json --output ../runs/new_raw_run
```

실행 흐름:
원본 영상 → 원래 OOOPS/사람 마스크/PanoVGGT/Poisson/의미 투표 → 통계적 객체 영역 →
전체 영상의 0.25초 구간별 최대 라플라시안 분산 후보 → 가시성·객체 품질 행렬 →
다중 시작점 탐욕 선정·국소 교체·추가 이득 종료 → 새 회차 정합 →
원본 RGB 전역/6방향/객체 확대 SimSaC → 묶음 처리 → 통합 뷰어.

입력은 순찰 매뉴얼·탐지 객체 목록·촬영 영상이다. 예제 중요도는 동일 매뉴얼과 객체 종류에
대한 저장된 5회 LLM 응답을 검증해 사용한다. 새 API 호출이나 모델 다운로드는 자동으로 하지 않는다.
새 매뉴얼을 썼다고 기존 점수를 새 LLM 평가로 표시하지 않는다.

CPU 최대 4스레드, 큰 작업 순차 실행, GPU 협력 잠금과 단계 마감을 유지한다.
원래 복원부터 다시 실행할 때 가용 메모리가 16GiB 미만이면 보호 중단한다.
다른 사용자 GPU 작업을 중단하지 않는다.

## 3. 이번 배포에서 확인한 범위

현재 계산은 `execution06/run`에서 뷰어까지 완료했다. 복원·의미 메시와 중요도 응답은
출처를 명시해 재사용했고, 전체 영상 선명도·새 후보·새 V/Q·선정·원본 프레임·정합·변화
추론은 이번 통합 작업에서 계산했다. 수정 영향이 없는 완료 단계만 해시로 검증해 이어 썼다.
과거 최종 키프레임이나 최종 검출 결과를 새 결과로 끼워 넣지 않았다.

- Dorm5: 전체 4,164프레임 검사, 후보 554개, 혼합 선정 10개. 공간/객체 조건의 8개/11개도 확인했다.
- 새 변화 결과: 원본 후보 5개, 규칙 기반 묶음 2개. 원본 후보 5개는 모두 `unresolved`이다.
- `verified_changes`라는 원래 필드명은 묶음 명칭이며, 독립 정답 검증이나 정확도 보증이 아니다.
- 원래 `targets_unmet`과 보간 자세·물리 축척의 `UNVERIFIED`는 숨기지 않았다. 지도 단위는 `u`이다.

## 4. 구현과 평가 실험의 구분

최종 프로그램은 **논문의 최종 혼합 선정 10개 지점을 변화 입력과 일관되게 연결**한다.
별도 효과 평가에 사용한 과거 변화 실험은 15지점 주변의 40/39프레임을,
현재 통합 실행은 10지점 주변의 30/30프레임을 비교했다. 과거 실험은 6후보/3묶음,
현재 실행은 5후보/2묶음이다. 비교 입력이 다른 이 결과 개수만으로 논문 방식의
구현 불일치를 판단하거나, 과거 평가의 개수를 최종 프로그램의 필수 출력으로 삼지 않는다.
현재 상자 변화의 반복 관측 근거가 부족한 것은 실행 결과의 한계로 남긴다.
알려진 상자 프레임을 강제로 추가하거나 옛 검출을 끼워 넣어 수치를 맞추지 않았다.

일반 사람의 의미 라벨은 유지된다. 실제 준비 영상 845개 모두 `capturer_only` 정책이며,
사람 변화는 RGB-person 분기로 탐지한다. 최대 3개 객체 확대 목록에서 사람이 빠지는 것은
채택한 원래 코드에도 있는 별도 처리로, 일반 사람을 변화탐지에서 제거한다는 뜻이 아니다.
LLM은 기존 동일 매뉴얼의 5회 점수 캐시를 사용한다. 보존된 요청 ID
`gemini-3.1-flash-lite`와 논문의 축약 명칭만으로 모델 교체나 알고리즘 차이를 주장하지 않는다.

전체 cold 복원은 RAM 부족으로 새 실행 검증하지 못했다. 이는 기존 복원 입력을 사용한
통합 연결 실행 완료와 구분한다. 상세 출처·시험·입력 대조는 `code/PAPER_PARITY.md`와
`evidence/execution06_parity_audit.json`을 따른다.

## 5. 주요 파일

- `code/`: 전체 계산 소스와 원래 생성기·선정·변화·뷰어 소스, 회귀시험
- `inputs/`: 필요한 소규모 의미/설정 입력과 검증된 중요도 캐시
- `demo/`: Dorm5 표시 전용 최소 자산
- `demo.py`: 표준 라이브러리만 사용하는 읽기 전용 뷰어 서버
- `RELEASE.json`: 배포 범위와 확인/미확인 상태
- `evidence/`: 코드 출처·해시·시험·입력 차이·실행 기록
- `MANIFEST.json`: 압축파일에 포함된 파일의 크기와 SHA256

```bash
python3 test_demo.py
cd code
python3 run_tests.py
```

데모 시험은 일반 컴퓨터에서, 전체 회귀시험은 외부 실행 환경이 갖춰진 서버에서 실행한다.
