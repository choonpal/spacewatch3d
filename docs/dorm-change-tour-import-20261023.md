# Dorm 정합·변화 결과를 Auto Tour로 연결

2026-10-23, 현재 작업의 기존 Auto Tour 360에 `Find Existing Map Alignment` 작업의 최신 Dorm 결과를 연결했다. 별도 실험 HTML이나 iframe을 붙이지 않고 기존 `변화 투어` 모드 안에서 맵·원본 360도·후보 목록을 구성했다.

## 실행과 입력

- 뷰어: `http://127.0.0.1:8768/?mode=changes&source=dorm`
- 기존 Rescan: `?mode=changes&source=rescan`. 촬영 데이터 선택에서도 전환 가능.
- 읽기 전용 입력: `D:/ChatGPT/Workspaces/Projects/jonghap_project/outputs/registration-benchmark-20261019/new-meshfirst-20261022`.
- 최신 판정: `automatic-lifecycle-v2/review.json`. 더 오래된 수동 45건 검토표나 두 의자 검토판정을 최신 자동 판정 대신 사용하지 않았다.
- 맵 출처: `/workspace/MESHTEST/experiments/dorm2_meshfirst_20261022`, `dorm3_meshfirst_20261022`의 smooth 메시에서 파생된 `maps/reference.bin`, `maps/after.bin`.
- 출력: `outputs/dorm-change-tour-20261023/published`. 큰 메시·사진은 Git 제외 산출물이다.
- 가져오기 도구: `tools/import_dorm_change_tour.py`. 새로운 탐지·분할 추론·정합 피팅은 수행하지 않는다.

```powershell
python tools/import_dorm_change_tour.py --source D:/ChatGPT/Workspaces/Projects/jonghap_project/outputs/registration-benchmark-20261019/new-meshfirst-20261022 --output outputs/dorm-change-tour-20261023/published
python apps/autotour360/server.py --port 8768 --dorm-tour-dir outputs/dorm-change-tour-20261023/published
```

출력 폴더는 새 경로여야 한다. 서버를 앱 폴더에서 실행할 때는 `--dorm-tour-dir`에 절대 경로를 쓰거나 기본값을 사용한다. 데이터가 없으면 먼저 가져오기를 실행해야 한다. clone만으로 실제 입력이 생기지는 않는다.

## 뷰어에 맞춘 표시

- 하나의 Auto Tour 화면 위쪽에 실제 Dorm 전체 메시, 아래쪽에 기준·비교 원본 파노라마, 오른쪽에 변화 후보와 보류 목록을 둔다.
- 맵은 겹쳐 보기 / 나란히 보기, 회전·이동·확대, 천장 숨기기, 촬영별 레이어 토글을 지원한다.
- 후보 목록 또는 지도 핀을 누르면 해당 구역과 실제 객체 메시를 강조하고 연결된 두 촬영의 원본을 표시한다.
- `객체 메시만`은 기존 원본 삼각형에서 추출된 메시만 표시한다. 상자나 생성 이미지로 객체를 대신하지 않는다.
- 사진은 기존 `Panorama` 렌더러를 재사용해 드래그·휠로 둘러본다. 원본의 대상 박스를 해당 시야에 투영한다. 반대쪽 예상 위치는 점선, 관측 영역은 실선으로 구별한다.
- 사진 박스 클릭으로 객체 메시만 보기 / 주변 맵으로 돌아가기를 전환한다. 사진 속 객체를 합성하거나 확인되지 않은 모양을 채우지 않는다.
- 버튼으로 13구역의 대표 원본을 이동하고, 각 후보에서 다른 확인 시점을 전환한다. 사진은 정지 상태를 유지한다.
- 실험용 대규모 수치표는 기본 화면에 두지 않고, 선택한 항목의 사유와 정합 오차를 `판정 근거`에 둔다.

## 판정·좌표 보존

최신 원본 결과는 **후보 2묶음**, **판단 보류 97항목**, 후보 제외 130항목, 묶음 문맥 11항목으로 총 238개 행이다. 한 묶음이 한 물체나 한 물리적 변화 건수를 뜻하지 않는다.

두 후보 모두 `possible_added`와 `possible_relocation` 대안을 가진다. 따라서 `이동·추가 가능`으로 표시하며, 두 유형 필터에 함께 나온다. 이를 이동 2건 + 추가 2건으로 합산하면 안 된다. 소실 가능 후보는 0개다. C092 테이블을 비롯한 보류 항목을 이동·소실로 바꾸지 않았다. 원본의 서로 다른 층 배치 비교라는 범위와 물리적 변화 정답 부재도 유지한다.

배경 맵의 전역·구역별 정합 행렬은 기존 결과를 그대로 사용한다. 객체 결과는 여기에 `alignment-context.json`의 구역별 `translation_bias_u`도 사용한다. 따라서 Dorm3 배경 메시의 해당 구역 정점에도 **같은 고정 잔차 이동**을 적용했다. 이 이동은 새로운 피팅이 아니다. 다른 구역의 공유 경계 정점은 원본 표시 파일에서 이미 복제되어 있어, 한 정점에 다른 구역의 이동을 중복 적용하지 않는다. 객체별 형상 맞춤 행렬은 변화 투어나 배경 맵에 사용하지 않았다.

- Dorm2 전체 삼각형 147,428개, Dorm3 전체 삼각형 147,432개를 그대로 유지했다.
- 표시 정점 75,031 / 75,064개에는 입력 표시 파일의 구역 경계 복제가 포함된다. 원본 고유 정점 수 73,696 / 73,714개와 구별한다.
- 전체 맵의 삼각형 인덱스 바이트는 입력과 일치한다. 메시를 다시 만들거나 구멍을 채우지 않았다.
- 후보 네 개의 촬영별 객체 메시 및 C092 정점의 맵상 일치는 최대 약 1.97e-6 u 이내였다. 이는 내보내기 float32 반올림 확인이며, 정합 자체의 정확도 수치가 아니다.
- u는 복원 좌표 단위다. 미터·cm·보정된 확률로 바꾸지 않는다.
- 원본의 전후 사진 쌍과 박스·시각을 유지한다. 서로 다른 촬영의 같은 프레임 번호를 같은 시점으로 가정하지 않는다.

## 구성과 확인

`change-tour.js`가 데이터에 따라 기존 Rescan 또는 새 Dorm 컨트롤러를 선택한다. `dorm-change-tour.js`는 기존 Auto Tour의 모드 전환 인터페이스를 구현하고, `dorm-tour-map.js`는 각 촬영의 깊이 버퍼를 따로 그려 합성한다. `dorm-tour-model.js`에서 불확실 분류, 이중 필터, seam을 건너는 파노라마 박스와 바이너리 형식을 다룬다.

`/dorm-tour/`는 공개 `tour.json`, 정해진 메시·사진 파일명만 제공한다. `import-audit.json`, 원본 NPZ, 임의 경로는 제공하지 않는다. 가져오기 감사 파일에는 입력 해시, 삼각형 보존, 전수 판정 보존, 복사한 파일별 해시가 남는다. 기존 source 파일이 가져오는 도중 바뀌면 실패한다.

확인 결과:

- 프런트엔드 테스트 74개 통과. 불확실한 이동/추가 대안을 확정 이동으로 바꾸지 않는 사례와 seam/잘못된 메시 입력 포함.
- HTTP 테스트 11개 통과. 공개 자산 분리, Range 요청, 비공개 파일 차단과 기존 Rescan 경로 보존 포함.
- 실제 입력 가져오기에서 238개 판정·2묶음·97보류를 원본과 전수 대조했고, 628개 자산을 복사했다.
- Chrome에서 13구역 사진, 지도 레이어, 객체 메시, 나란히/겹침, 후보 2묶음, C092 보류, 구역 이동 끝점, 둘러보기/변화 투어 왕복, 모바일 폭을 확인했다.
- 기존 Rescan 분류 12 / 이동9 / 추가2 / 소실1, 원래 영상 2개를 확인했다.

QA 기록은 앱 `.preview/dorm-tour-qa.json`, 맵-객체 좌표 대조는 `outputs/dorm-change-tour-20261023/map-object-placement-check.json`에 있다. 이 확인은 이식과 표시의 일관성 확인이며, 원래 변화 탐지 성능을 새로 평가한 결과가 아니다. 커밋·푸시는 수행하지 않았다.
