# 메쉬·원본 RGB 변화탐지

기본 변화탐지 버튼은 `/mesh-changes.html`로 연결됩니다. 입력 ZIP을 처음 넣으면
SimSaC를 실행하고 완료된 객체 결과를 표시합니다. 같은 입력·설정·모델은 검증된
결과를 재사용합니다. 실행 환경, 입력 규약과 검증 명령은
[mesh_simsac 안내](../../tools/mesh_simsac/README.md)를 참고하세요.
화면에는 변화 후보만 표시하며 분류별 필터·배지는 사용하지 않습니다. 박스를 누르면 해당 촬영 자신의 선택 객체만 전후로 강조합니다.

# AUTO TOUR 360

## 현재 변화 후보 비교

상단 **변화후보** 또는 `/mesh-changes.html`에서 전후 입력을 선택합니다. `?mode=changes`도 이 화면으로 연결됩니다. 서버 촬영 두 개 또는 입력 ZIP을 선택하면 입력 확인·정합·SimSaC·후보 정리·결과 표시가 자동으로 실행됩니다.

```sh
python apps/autotour360/server.py --port 4198 --mesh-change-runtime /path/to/runtime.local.json --mesh-change-jobs-dir /path/to/jobs
```

입력은 분할 메쉬·원본 RGB·카메라 포즈와 실제 점군입니다. 실행 환경과 서버 촬영 카탈로그는 로컬 설정으로 분리하며 저장소에 넣지 않습니다. 첫 입력에서 새 추론을 실행하고 동일 조건의 완료 결과는 재사용합니다. 완료 작업의 표시 코드만 바꿀 때에는 정합·추론을 다시 실행하지 않습니다.

## Dorm2 → Dorm3 전후 메시

상단 **Dorm 전후 메시** 또는 `residual-comparison.html?dataset=dorm2-dorm3`에서 기존 메시 비교 화면을 엽니다. 촬영 쌍 선택으로 Rescan·Bonn·Dorm을 전환합니다. 왼쪽 Dorm2, 오른쪽 상대 축척·좌표를 변환한 Dorm3를 나란히 표시하고, 구역을 선택하면 전후 원본 360° 파노라마에 같은 구역을 투영합니다. 지도 회전·이동·확대는 동기화되며, 원래 메시·변화 강조·상부 가리기·사진 이동·원본 확대를 지원합니다.

현재 결과는 변화 후보 18구역, 전후 사진 연결 18구역입니다. **정합은 복도 방향의 모호성이 남은 임시 추정**이며 화면 상단에서 안내합니다. 객체 분할 ID를 탐지에 사용하지 않지만, 입력 메시 자체는 기존 semantic 분할을 거쳐 만들어진 데이터입니다. `u`는 실측 미터가 아닌 Dorm2 복원 단위입니다. 서버 기본 산출물은 `outputs/dorm2-dorm3-20261019/run-v6/published`이며 다른 경로는 `--dorm-dir`로 지정합니다. [소스·계산·실행 기록](../../docs/dorm-mesh-comparison-20261019.md)

## 기존 Rescan 변화 투어

**기존 분류 복원:** `전체 12 / 이동 9 / 추가 2 / 소실 1`로 나눠 봅니다. 기존 `changes.json`의 종류를 그대로 표시하고, 정합 오차에 따른 재분류·보류 필터·기준 표면 확장 비교는 화면에서 제거했습니다. 객체를 누르면 추정 변위와 전후 원본 사진, 원본 객체 사진 겹침을 봅니다. 이 분류는 객체 주석과 자체 기하 계산에 따른 기존 결과이며 공식 변화 정답이 아닙니다.

기존 Auto Tour 상단의 **둘러보기 / 투어 편집 / 변화 투어**에서 모드를 전환합니다. 새 페이지나 iframe을 열지 않고 같은 뷰포트와 전체 화면 기능을 사용합니다. 이전/이후 촬영을 선택하고 **이전 지점 / 다음 지점**, 좌우 방향키, 썸네일로 정지 키프레임을 이동합니다. 영상 재생은 없습니다. 둘러보기 또는 투어 편집으로 돌아가면 기존 영상·시야·프로젝트를 유지합니다.

- 사진 속 변화 박스를 누르면 **원본 사진에서 객체만 잘라 반투명하게 겹칩니다.** 실제 사진의 색과 무늬를 유지하며 **주황 테두리는 이전**, **파랑 테두리는 이후** 객체입니다. 메쉬는 객체 윤곽과 촬영 시점 사이의 위치 변환에 사용합니다. 사각형 crop의 주변 배경을 함께 붙이지 않습니다.
- 객체 목록을 누르면 연결된 사진으로 이동합니다. 객체 표시 농도 조절, 닫기/Escape, 전후 원본 사진으로 이동을 지원합니다.
- 기존 `rescan-three-changes/changes.json`의 객체 대응·종류와 `*-object-mesh.bin`을 사용합니다. 새 탐지나 재정합은 수행하지 않습니다. 메쉬 경계에서 다른 객체와 섞인 삼각형은 객체 사진에 포함하지 않습니다.
- RGB 연결을 확인한 카메라의 원본 사진만 사용합니다. 원본 시점에서 메쉬 깊이·객체 ID를 확인하여 가려진 표면과 경계 1픽셀을 제외하고, 관측된 RGB만 현재 카메라로 재투영합니다. 관측하지 못한 면은 투명하게 남깁니다. 메쉬 누락·윤곽 오차·카메라 오차가 있으면 잘림이나 일부 배경 혼입이 생길 수 있으며, 별도의 픽셀 단위 분할 정답을 보장하지 않습니다. 현재 사진에서 가려진 과거 객체도 비교용으로 겹쳐 보입니다.
- 현재 입력은 Rescan scene_e_0/2의 연결된 7개 키프레임·12개 기존 변화 항목입니다. R0010004 촬영과 다른 공간이므로 그 360° 영상 위에 이 결과를 붙이지 않습니다. 우리 영상에서 같은 기능을 쓰려면 그 영상에 대응하는 전후 메쉬·변화 영역·카메라 좌표가 필요합니다.

기존 산출물이 있는 저장소 루트에서 다음과 같이 실행합니다.

```bash
python apps/autotour360/server.py --port 8768 --rescan-dir outputs/rescan-three-changes
```

브라우저에서 `http://127.0.0.1:8768/`을 열고 **변화 투어**를 누릅니다. Rescan으로 바로 진입하려면 `http://127.0.0.1:8768/?mode=changes&source=rescan`를 사용합니다. 기존 `change-tour.html` 주소도 이 모드로 연결됩니다. 이전의 `motion=local-error` 또는 `references=expanded` 주소로 열어도 현재의 기존 분류 화면을 표시합니다.

주변 오차 계산 코드·산출물은 실험 기록으로 보존하며 현재 변화 투어는 오차 분석 보고서를 읽지 않습니다. [첫 계산 기록](../../docs/local-motion-error-20261019.md) · [기준면 확장 기록](../../docs/expanded-motion-references-20261019.md)

## 최근 변경 · 2026-10-16: 메쉬 변화 후보와 전후 원본 사진

`residual-comparison.html`에 전후 메쉬의 국소 기하 차이를 살펴보는 화면을 추가했습니다. 상단 **촬영 쌍**에서 다음 두 결과를 선택합니다.

| 촬영 쌍 | 왼쪽 지도 | 오른쪽 지도 |
|---|---|---|
| Rescan · 기존 12개 위치 | 이전 메쉬 · 모든 방향 비교 | 이후 메쉬 · 모든 방향 비교 |
| Bonn · 새 상자 놓기 촬영 / 고정 설정 | 이전 메쉬 · 고정 설정 | 이후 메쉬 · 고정 설정 |

- 두 지도는 **왼쪽 이전 메쉬 / 오른쪽 이후 메쉬**로 고정합니다. 모두 모든 방향 3D 표면 비교를 적용하며, 드래그 회전·Shift+드래그 이동·휠 확대가 동기화됩니다. 아래 전후 원본 사진도 같은 순서로 배치합니다.
- **분류 / 위치**에서 후보나 공통 구조면을 선택합니다. 아래에 선택 위치의 전후 원본 정지 사진을 나란히 표시하며, 화살표로 다른 사진을 보고 **원본 크게 보기**로 확대합니다. 자동 재생하지 않습니다.
- 두 지도의 **주황**은 변화 의심 표면, **청록**은 후보에서 제외한 공통 구조면, **회색**은 비교 근거 부족입니다. 각 지도 아래에는 해당 촬영의 후보 표면 면적을 표시합니다. **표면 거리 / 노이즈 기준**, **원래 메쉬** 표시도 양쪽에 함께 적용합니다.
- 공통 바닥·수직 구조면의 표면만 제외하고, 가구의 모든 방향에서 양방향 3D 표면 거리를 비교합니다. 국소 요철, 반경 8·16·28cm 중 두 크기 이상에서 6cm 및 노이즈 기준 초과, 연결된 표면 조건을 적용합니다. 정식 M3C2 단독 판정은 아닙니다. 예전 방식과의 비교 칼럼·전환 버튼은 화면에서 제거했습니다.
- Rescan의 **12개 위치별 결과**는 기존 항목에 후보가 포착됐는지를 보여줍니다. 기존 종류 라벨은 탐지 후 참고용이며 새 자동 객체 분류 결과가 아닙니다. 12/12 포착을 정확도 100%로 해석하지 않습니다.
- 새 Bonn 촬영은 바닥 기준 3.79/3.62/3.42cm와 기존 검출 설정을 고정한 첫 실행입니다. 후보 6패치 중 01번은 새로 놓인 상자 부근에 잡혔습니다. 모든 후보를 표시하고, 사진이 연결되지 않은 시점은 비워 둡니다. 복원 누락·가림에 따른 차이도 후보에 포함될 수 있습니다.

저장소 루트에서 서버를 실행합니다. 데이터가 이미 생성되어 있어야 합니다.

```bash

```

브라우저에서 `http://127.0.0.1:8768/residual-comparison.html` 또는 `http://127.0.0.1:8768/residual-comparison.html?dataset=bonn-placement`를 엽니다.

기본 출력 위치는 Rescan `outputs/all-surfaces-rescan-v2-20261016/published`, 새 Bonn `outputs/frozen-transfer-bonn-placement-20261016/run-v1/published`입니다. 다른 결과는 `--residual-dir`와 `--transfer-dir`로 지정합니다. `data/`, `outputs/`의 실제 영상·깊이·메쉬·사진은 Git에 포함하지 않습니다.

새 Bonn 실행 예시(원본 데이터와 계산 의존성이 준비된 환경):

출력 경로는 매번 새로 지정합니다. 고정한 계산 소스가 바뀌면 실행을 중단합니다. 소스 SHA256를 보존하기 위해 기록 대상 파일은 `.gitattributes`에서 Git 줄바꿈 자동 변환을 제외했습니다. 같은 Bonn 공간의 다른 영상에서 앞·뒤 구간을 각각 복원한 것이며, 두 번의 독립적인 방문 스캔은 아닙니다. 변화 정답 라벨은 읽지 않고, 제공 카메라 위치·자세는 3D 좌표 복원과 사진 연결에 사용합니다.

상세 계산·원본 출처·기존 실패와 한계는 [메쉬 변화 비교 기록](../../docs/residual-roi-comparison-20261016.md)에 있습니다.

## 최근 변경 · 2026-10-12

점군 위와 영역 목록에 **제거 후보·추가 후보** 라벨을 붙였습니다. 이동 결과에 미터 단위 변위가 제공되면 **이동 · 0.75 m**처럼 표시합니다. 현재 데이터에는 객체 대응 정보가 없어 객체 이동 거리는 **산정 불가**로 표시하며, 표면 간 최근접 거리와 분리합니다.

상단 **3D 변화 근거** 링크에서 실제 MultiChange3D 전후 점군을 비교합니다. 5개 변화 영역 선택, 전후 시점 동기화, 변화 강조·원본 색상 전환, 원본 점 번호·표본 거리 확인과 다운로드를 지원합니다.

원본 전체 점군은 거리 비교의 상대 데이터로 사용하고, 측정은 공간 표본 14,340점에 한정합니다. 객체 동일성·가림·빈 공간·전후 영상 근거는 입력이 없어 추가 검증 상태로 표시합니다. 공식 변화 라벨을 사용하는 근거 생성 데모이며 탐지 모델의 성능 평가가 아닙니다. 실행과 데이터 다운로드는 [데모 문서](../../docs/change-evidence-demo.md)를 참고하세요.

브라우저에서 **http://127.0.0.1:8766/** 를 엽니다. Windows에서는 `start.bat`을 실행합니다. 서버 종료는 실행 터미널에서 `Ctrl+C`입니다.

다른 PC에서 처음 실행할 때는 Python 3.10 이상, FFmpeg(`ffmpeg`와 `ffprobe`를 PATH에 등록)를 준비하고 `setup-trajectory.sh`를 한 번 실행하세요. Windows에서는 `setup-trajectory.bat`입니다. 이후 `start.sh` / `start.bat`으로 실행합니다. 최초 패키지 설치에는 인터넷이 필요하며, 설치 후 분석과 재생은 외부 서비스 없이 로컬에서 처리합니다.

### FFmpeg 설치 및 확인

사용하는 운영체제에 해당하는 명령만 실행하세요. FFmpeg 패키지에는 영상 정보를 읽는 `ffprobe`도 포함됩니다. **두 명령의 버전 정보가 모두 출력되면** 준비된 상태이며, 이미 정상 실행된다면 다시 설치할 필요가 없습니다.

#### Ubuntu / Debian

터미널에서 설치하고 실행 경로와 버전을 확인합니다. 패키지 관리자로 설치하면 일반적으로 PATH를 직접 수정할 필요가 없습니다.

```bash
sudo apt update
sudo apt install -y ffmpeg

command -v ffmpeg
command -v ffprobe
ffmpeg -version
ffprobe -version
```

일반적인 실행 경로는 `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`입니다. 배포판별 패키지는 [FFmpeg 공식 다운로드 안내](https://ffmpeg.org/download.html)에서도 확인할 수 있습니다.

#### Windows 10 / 11 — PowerShell

WinGet으로 [Gyan의 FFmpeg Windows 패키지](https://www.gyan.dev/ffmpeg/builds/)를 설치합니다. `--id`, `--exact`, `--source` 옵션은 설치할 패키지를 지정합니다. [Microsoft 설치 명령 안내](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)

```powershell
winget --version
winget install --id Gyan.FFmpeg --exact --source winget
```

설치가 끝나면 **Windows Terminal / PowerShell 창을 완전히 닫고 새로 연 뒤** 확인합니다. 편집기 안의 터미널이라면 편집기도 다시 실행하세요.

```powershell
where.exe ffmpeg
where.exe ffprobe
ffmpeg -version
ffprobe -version
```

WinGet이 인식되지 않으면 [Microsoft의 WinGet 설치 안내](https://learn.microsoft.com/en-us/windows/package-manager/winget/#install-winget)에 따라 **앱 설치 관리자(App Installer)**를 설치하거나 업데이트한 뒤 다시 실행하세요. FFmpeg ZIP을 직접 내려받아 압축을 푼 경우에는 `ffmpeg.exe`와 `ffprobe.exe`가 들어 있는 `bin` 폴더를 사용자 환경 변수 `Path`에 추가하고 터미널을 다시 열어야 합니다.

#### macOS — Homebrew

Homebrew가 설치된 터미널에서 [공식 FFmpeg Formula](https://formulae.brew.sh/formula/ffmpeg)의 설치 명령을 실행합니다.

```bash
brew install ffmpeg

command -v ffmpeg
command -v ffprobe
ffmpeg -version
ffprobe -version
```

`brew`가 인식되지 않으면 [Homebrew 설치 안내](https://brew.sh/)에 따라 설치하고, 설치 마지막에 표시되는 `brew shellenv` 설정을 적용한 뒤 새 터미널에서 실행하세요.

### FFmpeg 준비 후 최초 설정과 실행

Python 3.10 이상이 준비된 상태에서 진행합니다. 아래 앱 폴더 경로는 각 PC에 프로젝트를 저장한 실제 경로로 바꾸세요.

## 사용 흐름

1. 시작 화면의 **360° 영상 선택**을 누르거나 영상을 끌어다 놓습니다. 여러 영상도 선택할 수 있습니다.
2. 영상이 PC에 보관되면 **분석이 자동으로 시작**됩니다. 별도 분석 시작 버튼을 누를 필요가 없습니다. 동시에 입력한 영상들은 순서대로 분석합니다.
3. 영상이 바로 열리며, 상단에서 프레임 추출·촬영 위치 복원 등의 진행 상태를 확인할 수 있습니다. 분석 취소·재시도가 가능합니다.
4. 완료되면 동선 지도와 영상 속 바닥 화살표가 표시됩니다. 영상 위 경로 선과 지도 옆의 별도 방향 버튼은 표시하지 않습니다.
5. **바닥 화살표로 연결된 촬영 지점으로 이동**합니다. 바닥 화살표 이동은 영상을 정지하며, 카메라가 회전한 구간에서도 바라보던 방향을 유지합니다. 파란색은 이후 경로, 주황색은 지나온 경로입니다. 미니맵의 경로도 클릭·탭할 수 있습니다.
6. 드래그·Q/E로 시선을 바꾸고 휠·두 손가락으로 확대합니다. 분석된 경로가 있는 둘러보기 모드에서는 방향키가 시선 방향에 연결된 지점으로 이동합니다. 이동 지점은 같은 연결 구간의 관측 위치에서 고르며, 경로 끝·분석 실패 구간·연결되지 않은 방향에는 이동 버튼을 활성화하지 않습니다. 미니맵에 초점을 두면 방향키로 5초씩 이동합니다.
7. **투어 편집**에서 장면 이름·설명을 바꾸고 설명 지점 또는 사용자 지정 연결을 추가할 수 있습니다. 이전/다음 지점 버튼은 자동 생성하지 않습니다.
8. **투어 저장**으로 경로·장면·설정이 담긴 JSON을 내보냅니다. 브라우저 다운로드와 함께 저장소의 `outputs/virtual_tour/tours/` 폴더에도 파일이 남습니다. **내 영상**에서 보관한 영상을 다시 열 수 있습니다.

**촬영 경로** 버튼은 깃허브 원본의 자동 촬영 경로 설정 창을 엽니다. 경로 표시 여부, 미니맵, 앞뒤 표시 범위, 바닥 높이 설정과 재분석·분석 취소 기능을 제공합니다. 분석 전에는 **자동 경로**, 분석 중에는 **경로 분석 중**으로 표시됩니다.

## 투어 이동 키프레임 선별

촬영 경로 분석이 끝난 영상을 열고 **키프레임 선별 → 자동 선별 시작**을 누릅니다. **적게 / 보통 / 촘촘하게**로 이동 지점 수를 조절할 수 있습니다.

- 구간 시작·끝과 주요 동선 꺾임을 유지하고, 이동 거리를 기준으로 중간 지점을 추가합니다. 정지 구간과 꺾임 바로 옆의 중복 지점은 줄입니다.
- 각 관측 시각의 원본 영상을 별도 디코더로 읽습니다. 360도 화면의 적도 부근에서 이미지 디테일(라플라시안 분산)과 밝기를 비교해, 거리 기준 후보를 가까운 선명한 관측으로 옮길 수 있습니다. 시작·끝과 꺾임은 이동하지 않습니다.
- 선별 결과는 영상 아래 미리보기 목록에 표시됩니다. 미리보기를 누르면 해당 원본 시각으로 이동하고, 바닥 화살표와 방향키는 앞뒤의 선별 지점으로 이동합니다. 미니맵에는 선별 지점을 보라색 점으로 표시합니다.
- 바닥 화살표·방향키·키프레임 미리보기로 지점을 옮길 때, 출발 화면이 이동 방향으로 살짝 확대되고 도착 화면으로 약 0.42초 동안 부드럽게 겹쳐 전환됩니다. 사이 구간의 영상을 재생하지 않으며 이동 후에도 해당 시각에서 정지합니다. 시야 방향과 확대 수준을 유지합니다.
- 전환 중 추가 이동은 차단합니다. 드래그·확대·일반 타임라인 탐색·장면 변경으로 전환을 취소할 수 있습니다. 영상 응답 지연이나 오류 시 화면 효과를 정리하며, 시스템의 동작 줄이기 설정이 켜져 있으면 애니메이션 없이 이동합니다. 일반 영상 재생과 타임라인 탐색에는 이동 효과를 적용하지 않습니다.
- **선별 설정 → 선별 지점으로 바닥 화살표 이동**을 끄면 기존 이동 방식으로 돌아갑니다. 기존 촬영 경로 설정의 앞뒤 표시 범위는 기존 이동 방식에 적용됩니다. 선별 모드에서는 다음 선택 지점이 오래 정지한 구간 뒤에 있어도 이동할 수 있습니다.
- 경로 분석이 끊긴 구간은 연결하지 않습니다. 선별 중 취소할 수 있고, 영상을 바꾸면 진행 중인 선별을 중단합니다. 선별 중에는 현재 뷰어의 재생 시각이나 시선을 바꾸지 않습니다.
- 결과는 영상별 `tourKeyframes`에 저장됩니다. 원본 SHA-256, 촬영 경로 fingerprint, 관측 인덱스·시각, 선택 이유, 품질 비교값, JPEG 미리보기를 투어 JSON으로 내보내고 다시 불러올 수 있습니다. 간격을 바꿔 다시 선별할 때는 저장한 품질 비교값을 재사용합니다. 원본이나 재분석 경로가 바뀌면 다시 선별합니다.

이 기능은 **투어 이동 지점**을 고릅니다. 객체 ID를 입력받는 파이프라인 **Task 5b의 객체별 대표 프레임 선별**은 구현하지 않습니다. 간격은 추정된 상대 거리와 카메라 높이에 맞추며 실제 미터 단위가 아닙니다. 이미지 점수는 디테일 비교를 위한 휴리스틱으로, 객체 가시성·방별 커버리지·벽 뒤 가림이나 경로 정확도를 보장하지 않습니다. 360도 전체를 볼 수 있으므로 카메라 회전만으로 이동 지점을 추가하지 않습니다.

## 파일과 저장

- 입력 영상과 원본 정보: `data/virtual_tour/<영상 SHA-256>/input.mp4`, `source.json`
- 경로 JSON, 분석 상태, 특징점 데이터베이스, 로그: `outputs/virtual_tour/analysis/<영상 SHA-256>/`
- 같은 내용의 영상을 다시 입력하면 같은 원본과 기존 분석 결과를 재사용합니다.
- 서버를 껐다 켜도 영상 목록과 분석 결과를 다시 불러옵니다. 브라우저를 닫아도 실행 중인 서버는 분석을 계속합니다.
- 장면 편집·설명·표시 설정은 브라우저 `localStorage`의 `autotour360.project.v1`에 저장합니다. 다른 브라우저나 PC로 옮기려면 JSON과 원본 영상을 함께 보관하세요. 영상 자체는 JSON에 포함되지 않습니다.
- 브라우저 보관 데이터를 삭제해도 서버의 영상·경로는 남지만, 사용자 편집 내용은 내보낸 JSON이 있어야 복원할 수 있습니다.
- 캐시는 파일시스템에만 저장되며 외부 서비스에 전송하지 않습니다. 다른 기기에서 접속해 입력하면 프로그램이 실행 중인 PC로 전송됩니다.
- `outputs/virtual_tour/tours/`에는 직접 저장한 투어 JSON 파일이 보관됩니다. 브라우저에서 다운로드가 제한되어도 이 파일로 복원할 수 있습니다.
- 위 데이터·결과 경로는 저장소 루트 기준입니다. `data/`, `outputs/`, 앱의 `.venv/`, `.preview/`는 Git에서 제외됩니다.

## 입력과 분석 범위

| 항목 | 지원 |
| --- | --- |
| 입력 | 스티칭이 완료된 단안 2:1 equirectangular 영상 |
| 권장 코덱 | MP4/H.264. MOV·WebM 등은 브라우저와 FFmpeg의 코덱 지원에 따름 |
| 한도 | 파일당 최대 2GB, 3초 이상·10분 이하 |
| 분석 | 약 2fps 추출, CPU PyCOLMAP 구면 SfM, 관측 특징점에서 바닥 평면 추정 |
| 조작 | PC 마우스·키보드, 모바일 터치, 전체 화면 |
| 경로 이동 | 영상 위 경로·미니맵 클릭으로 해당 시각에 이동. 분석 실패 구간은 연결하지 않음 |

경로는 녹화된 영상에서 추정한 **카메라의 촬영 동선**입니다. 촬영하지 않은 미래 길을 예측하거나 공간 안에서 자유롭게 걸어 다니는 3D 메시 뷰어는 아닙니다. 단안 영상의 거리 단위는 상대값이며, 실제 측량값과 비교한 위치 정확도는 제공하지 않습니다. 화면의 ‘촬영 구간 연결 비율’은 분석된 시간 구간의 비율입니다.

흔들림, 반복 무늬, 특징이 적은 벽, 움직이는 사람, 조명 변화 등으로 분석이 실패하거나 경로가 틀어질 수 있습니다. 벽·물체 뒤 경로의 가림 처리, 계단·다층 바닥, 듀얼 어안 스티칭, 입체 360 영상, 실시간 SLAM은 지원하지 않습니다. 자동 분석에 실패해도 영상을 둘러보고 재생 막대로 이동할 수 있습니다.

## 다른 실행 옵션

원본을 복사하지 않고 지정 경로에서 직접 분석·재생할 수도 있습니다.

```bash
python3 server.py --media "/path/to/video.mp4" --open
```

이 경우 다음 실행에도 같은 `--media` 인수를 사용해야 합니다. 파일 선택으로 입력한 영상은 인수 없이 복원됩니다.

같은 Wi-Fi의 휴대전화에서 열려면 `python3 server.py --host 0.0.0.0`으로 실행하고 `http://PC의-로컬-IP:8766/`로 접속합니다. 기본은 이 PC에서만 접속 가능한 `127.0.0.1`입니다.

입력·출력 폴더는 옵션으로 지정할 수 있습니다. 상대 경로는 실행한 터미널 위치와 관계없이 **앱 폴더 기준**입니다.

```bash
python3 server.py --data-dir "/path/to/videos" --output-dir "/path/to/results" --open
```

`--output-dir` 아래에는 `analysis/`와 `tours/`가 생성됩니다. 서버 시작 메시지에 실제 저장 위치가 표시됩니다. 기본 데이터 경로를 사용하려면 저장소의 `apps/autotour360/` 위치를 유지하세요.

## 이전 독립 앱의 데이터 가져오기

기존 앱에서 실행 중인 분석을 완료하거나 취소하고, 브라우저에서 **투어 저장**을 누릅니다. 이후 아래 명령으로 영상·경로·투어 파일을 복사합니다. 이미 다른 내용의 파일이 있는 대상은 덮어쓰지 않으며, 모든 복사 파일의 SHA-256을 검증합니다. 원본 폴더는 유지됩니다.

```bash
python3 migrate_legacy.py "/path/to/old/autotour360"
```

이관 기록은 `outputs/virtual_tour/migration-*.json`에 남습니다. 같은 호스트·포트·브라우저로 접속하면 기존 브라우저 설정을 계속 사용합니다. 다른 주소나 브라우저로 열 때는 저장한 투어 JSON을 불러오세요.

### Dorm2 / Dorm3 정합 겹침 보기

`/residual-comparison.html?dataset=dorm2-dorm3`는 변화 탐지 전 정합 확인 화면이다. Dorm2(주황)와 Dorm3(청록)를 겹쳐서 보고, 바닥·벽만 표시하거나 각 메시를 끌 수 있다. 좌표 보정 전 / 이전 임시 정합 / 새 전체 구조 정합을 같은 기준으로 비교한다. 기본 `--dorm-dir`은 `outputs/dorm2-dorm3-20261019/alignment-v9/published`이며, 원본 두 메시를 보존한 상대 축척/회전/이동만 적용한다. u는 실측 미터 단위가 아니다.

원본 파일 연결 기록은 일치하지만 영상 안내판은 5F/3F로 달라 동일 장소가 확인되지 않았다. 화면에 미해결 상태를 명시한다. 새 구조면 겹침 45.6%는 기하 표본의 겹침이며 실제 변화 판정이나 동일 장소 증명을 뜻하지 않는다. 자세한 계산/재현/원본 연결 점검은 `docs/dorm-mesh-comparison-20261019.md`에 기록했다.

# 분할 메쉬 검증 화면

완료된 작업의 입력을 따로 검토하려면
`/mesh-segmentation.html?job=<작업 ID>`를 연다. 기존 변화 결과는 그대로 두고,
각 촬영 자신의 분할 메쉬를 자신의 원본 ERP와 카메라 포즈에 투영한다.
등록된 입력으로 표시용 파일을 한 번 준비하며 정합·SimSaC·분할 추론은 다시 실행하지 않는다.

전후 프레임과 객체 ID를 각각 선택하고, 메쉬 투명도·2D 마스크 윤곽·사람 가림 제외·
삼각형 선·RGB 배경을 조절할 수 있다. 아래 두 3D 화면은 분할된 삼각형을 직접 표시한다.
초록 윤곽은 입력 2D 마스크, 분홍 윤곽은 메쉬 ID가 연결되지 않은 2D 분할이다.
마스크로 메쉬를 잘라 맞추거나 반대 촬영의 메쉬를 이 화면에 투영하지 않는다.
객체 색과 번호는 촬영별 ID이며 전후 동일 객체를 뜻하지 않는다.
