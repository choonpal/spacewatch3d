# Dorm4·Dorm5 키프레임 단독 제거 분석

## 목적과 입력

2026년 10월 28일, SpaceWatch3D 7.0.0-dev.17의 Dorm4 19개 및 Dorm5 21개 선택 지점에서 한 지점씩 제외하는 40개 비교를 수행했다. 기존 계획의 객체별 관측 품질과 관측 가능 분모를 고정하고, 공간 가시성은 원래 코드와 표본 규칙으로 CPU 재평가했다.

## 방법

주 선정 표본은 seed 20261025와 표면 표본 6,000개다. 보완 표본 두 개는 표면 및 객체·구역 최소 표본 수를 두 배로 사용했다. 독립 검증 표본 두 개는 표면 표본만 두 배로 사용했다. 총 5개 표본에서 원본 표면 관측률을 먼저 재현했으며 두 입력의 10개 조합에서 오차는 10⁻⁸ 미만이었다. 객체 품질은 각 지점 제거 후 남은 관측의 최대값으로 다시 계산했다.

## 결과

| 항목 | Dorm4 | Dorm5 |
| --- | ---: | ---: |
| 기존 선택 지점 | 19 | 21 |
| 제거 후 기본 객체 개수 목표 90% 유지 | 0 | 7 |
| 추가 품질 여유 조건 유지 | 0 | 0 |
| 기본 객체 목표 유지 및 새 공간 목표 미달 없음 | 0 | 3 |
| 새 공간 목표 미달 발생 | 3 | 12 |

Dorm5의 frame859, frame960, frame3376은 각각 단독 제거 시 기본 관측 113/125개를 유지했다. 추가 품질 여유 조건을 적용하면 112/125개로 감소했다. 각 지점에서 천장등 영역 한 개가 기준 미달로 바뀌었다. 당시 실행 시간은 약 41.14초다.

위 결과는 단독 제거 영향이다. 여러 지점 동시 제거, 후보 교환 및 이동 경로 재구성은 평가 범위 밖이다. 실제 객체 동일성과 영상 가독성 GT가 부족해 안전한 삭제나 전역 최소 지점 수를 확정하지 않았다.

## 재현과 파일

- `analyze_server_r2.py`는 당시 원본 계획·장면과 CPU 가시성 구현을 읽는 실행 코드다. Linux 경로와 원래 native_executor 환경에 의존한다.
- `results/summary.json`과 `results/diagnostic_summary.json`은 당시 실행 결과 요약이다. before는 Dorm4, after는 Dorm5다.
- `validation.json`은 당시 별도 NumPy 교차검증 기록이다. 업로드 시 새 공간 가시성 계산은 실행하지 않았다.

기존 코드 경로와 pair_result/results.json이 준비된 환경에서 실험 스크립트를 새 작업 폴더에 두고 실행한다. 스크립트는 해당 폴더의 results_r2를 새로 생성한다.

```sh
python -B analyze_server_r2.py
```

주요 환경은 NumPy, 원래 SpaceWatch3D task_5b_keyframes 코드, 이미 빌드된 native_executor/rays 라이브러리 및 당시 계획과 scene 입력이다. 객체 품질 0.35, 추가 여유 최대 0.05, 객체 목표 0.9, 구역 목표 0.6은 원래 실행 조건을 사용했다.
