# 기존 브랜치에서 task 구조로 이관

2026-09-27 확인 시 main은 문서 중심이며, 실제 실험·스크립트는 별도 브랜치에 있습니다.
이번 구성에서는 기존 브랜치 또는 열린 PR을 병합·삭제·수정하지 않았습니다.

| 기존 브랜치 | 확인한 내용 | 이관 후보 |
|---|---|---|
| `kdj` | `scripts/video_to_mvs.py`, COLMAP/OpenMVS 자동화, 영상·프레임·점군 산출물 | Task 1a의 추출 로직, Task 2의 COLMAP/OpenMVS 대안 adapter |
| `wooh594-for-commit` | SAM2 실험·평가 스크립트, 의미 지도 계획 | Task 3의 비교 실험 또는 분할 adapter |
| `library-cleanup` | LingBot 시각화, MV3DIS/SpaCeFormer 비교 및 GLB 관련 실험 기록 | Task 2·3·4의 참고 자료와 시각화 유틸 |
| `gwanwoo3849-for-commit` | 웹 초안·발표자료 | 추후 관제 UI 연동 시 재사용 검토 |
| `lth` | 작업일지 | 담당 task의 실험 노트로 이동 검토 |

이는 코드 위치에 따른 제안이며 사람별 담당을 지정한 것이 아닙니다. 실험 결과가 있다는 이유로 공통 pipeline backend가 이미 완성된 것으로 표시하지 않습니다.

## 필요한 부분만 옮기기

1. 기존 브랜치의 작업을 커밋해 보존합니다.
2. 최신 `main`에서 새 task 브랜치를 만듭니다.
3. 필요한 코드만 가져와 해당 task 디렉터리에 배치합니다.
4. 고정 경로·전역 설정을 `TaskRequest`와 `config` 입력으로 바꿉니다.
5. 입출력을 `docs/contracts.md`에 맞추고 작은 사례로 검증합니다.
6. 기존 브랜치명·commit과 비교 결과를 PR에 기록합니다.

단일 task 변경만 담긴 커밋은 cherry-pick할 수 있습니다. 영상·가중치·대형 산출물이 함께 들어 있는 커밋은 통째로 가져오지 말고 필요한 코드를 선별합니다.
열린 기존 PR #1, #2는 원래 작업 검토용으로 유지하며, 자동으로 닫거나 병합하지 않습니다.
