# Dorm 전체 메시에서 변화 의심 구역 찾기

현재 Auto Tour의 Dorm 변화 투어는 객체 중심 자동 분류를 기본으로 가져오던 이전 버전 대신, 전체 삼각형 표면에서 공간 차이를 먼저 계산한다. 객체 분할이 붙거나 나뉜 정도, 의자 개수, 같은 객체라는 대응은 후보 생성 조건이 아니다.

## 입력과 계산

- 읽기 전용 소스: `D:/ChatGPT/Workspaces/Projects/jonghap_project/outputs/registration-benchmark-20261019/new-meshfirst-20261022`.
- 읽는 입력: 전체 `maps/reference.bin`, `maps/after.bin`, 구역별 삼각형 범위와 고정 정합/오차 정보, 원본 카메라 poses, 원본 JPEG.
- `automatic-lifecycle-v2`, semantic instance 목록, 영상 객체 트랙, YOLO 마스크, 변화 정답은 읽지 않는다. 원본 JPEG의 기존 캐시 폴더 이름은 `object-comparison-v1/photos`이지만 그 폴더에서는 사진만 읽는다.
- 입력 메시는 기존 복원 결과다. 새 계산에서 객체 분할을 사용하지 않는다는 뜻이며 입력 메시 자체가 완전하거나 원래 복원이 분할의 영향을 받지 않았다는 뜻은 아니다.
- 기존 전역/구역 정합과 잔차 이동은 그대로 사용한다. 새 정합, 객체별 정합, 메시 변형·구멍 메우기는 하지 않는다.

양방향으로 각 삼각형 내부의 네 점에서 반대 전체 메시의 **삼각형 표면까지 실제 최단 거리**를 계산한다. 법선 방향에 투영하는 M3C2 구현은 아니다. 바닥/벽/가구라는 의미 분류나 법선 방향 필터를 탐지 표면에 걸지 않는다.

구역 z의 고정 구조 정합 오차를 E_z, 두 맵에서 가깝고 평행한 표면의 삼각형 내부 거리 변동을 N_z라 할 때, 최종 기준은 다음과 같다.

`T_z = max_epoch(sqrt(E_z^2 + (2.5 * N_z)^2))`

N_z는 대응 거리 E_z 이하이고 법선 내적 절댓값 0.94 이상인 삼각형들에서, 네 샘플의 중심 샘플 대비 절대 거리 변동을 중앙값으로 요약한다. 안정 표본 80개 미만이면 추가 잡음을 추정하지 않고 기존 E_z를 유지한다. E_z 자체는 원래 구조 정합 산출물의 보수적인 거리 예산이다. 이 T_z를 통계적으로 보정된 95% 검출한계나 변화 확률이라고 부르지 않는다. 단위 u는 복원 좌표 단위이며 미터가 아니다.

삼각형의 네 점 중 75% 이상이 T_z를 넘고, 가까운 표면의 과반이 같은 차이를 지지해야 한다. 그 삼각형들끼리만 연결하므로, 변하지 않은 바닥이나 연결된 의자 표면을 경유해 객체 전체를 묶지 않는다. 고립된 점/작은 조각을 거르기 위해 6개 삼각형, `0.0064 * height^2` 면적, `0.09 * height` 길이를 요구한다. 가까운 원래 메시 조각은 `0.035 * height` 이내에서 연결할 수 있다. 모든 구역에 동일 정책을 사용하며 특정 의자/구역의 정답을 보고 임계값을 조정하지 않았다.

## 변화 의심과 판단 보류

**변화 의심 구역**은 기하 차이 조건에 더해, 원래 표면을 볼 수 있는 서로 떨어진 원본 카메라 시점 2개와, 반대 맵에서 그 위치보다 뒤의 표면을 보는 시점 2개가 있어야 한다. 같은 카메라 위치의 연속 프레임은 중복 관측으로 세지 않는다. 객체 검출·클래스 일치 조건은 없다.

반대 맵을 향한 광선이 표면을 못 만난 경우는 비점유 근거가 아니다. 원본 표면 관측 부족, 가림/복원 누락, 정합 방향 제약 부족은 **판단 보류**로 남긴다. 정합 normal rank가 부족한 R07/R09/R10/R11은 충분한 방향 근거를 새로 추정하지 않았으므로 이들 구역의 차이를 확정 후보로 승격하지 않는다.

광선 검사는 입력 메시와 추정 카메라의 일관성 검사다. 원본 사진은 연결해 보여주지만 독립적인 원본 깊이 검증이나 RGB 의미 판단은 수행하지 않았다. 반복적인 복원 오류가 공간적으로 이어지는 경우, 얇은 물체, 매우 작은 이동은 여전히 오탐/미탐 가능성이 있다. 원본 프로젝트의 서로 다른 층 배치 비교라는 기록과 실제 변화 정답 부재도 해결한 것으로 취급하지 않는다.

화면의 0–100 점수는 `50 * clip((거리배율-1)/2) + 25 * 공간일관성 + 25 * clip(반대 비점유 독립시점수/2)`이다. 확률·정확도가 아닌 근거 요약 점수이며, 후보/보류 판정은 점수 순위로 바꾸지 않는다.

## 실제 결과와 화면

- 입력 삼각형: Dorm2 147,428 / Dorm3 147,432, 합계 294,860개 전수 비교.
- 공간 연결 결과: 50구역 중 변화 의심 **28구역**, 판단 보류 **22구역**.
- 의심 구역의 강조 삼각형: Dorm2 1,783 / Dorm3 2,390. 객체 전체 메시를 강조하지 않는다.
- R08: 의심 8구역. 이는 의자 8개나 이동 8건을 뜻하지 않는다. 예를 들어 P0022는 차이 중앙값 0.332 u / 구역 오차 약 0.117 u, 약 2.8배인 표면을 표시한다.
- 보류 사유: 가림/복원 누락 14, 원래 표면 관측 부족 8구역. 현재 구역 경계를 넘어 반대 전체 메시를 조회하므로, 경계 너머에 존재하는 표면을 누락으로 오해한 차이가 줄었다.

같은 Auto Tour의 `?source=dorm&mode=changes`에서 위쪽에 두 메시를 나란히, 아래쪽에 각각의 추정 카메라로 투영한 원본 360도 사진을 표시한다. 회색은 주변 전체 메시, 주황/청록은 선택된 차이 삼각형이다. `차이 메시만`과 `선택 해제`를 지원한다. 사진의 박스는 차이 위치의 기하 투영 범위이며 독립적인 이미지 객체 분할 결과가 아니다. 이동·추가·소실을 자동 확정하지 않고 **변화 의심 구역**으로 표시한다.

## 실행

```powershell
python tools/build_dorm_surface_changes.py --source D:/ChatGPT/Workspaces/Projects/jonghap_project/outputs/registration-benchmark-20261019/new-meshfirst-20261022 --output outputs/dorm-surface-change-20261023/run-v3/published
python apps/autotour360/server.py --port 8768 --rescan-dir outputs/rescan-three-changes
```

출력은 실행마다 새 폴더여야 한다. 이미 존재하는 run-v3는 재사용하지 말고 새 폴더를 지정한 다음 서버 `--dorm-tour-dir`로 선택한다. 원본 입력 해시, 정책, 구역별 필터 통계, 강조한 원래 삼각형 ID, 사진 해시는 비공개 `surface-audit.json`에 기록한다. 기존 객체 중심 가져오기 결과는 `outputs/dorm-change-tour-20261023/published`에 보존되어 있으며 `--dorm-tour-dir`로 다시 표시할 수 있다.

확인: 연결된 단일 메시의 국소 변화와 방향 독립성, 오차 이내 정합/잡음, 고립된 큰 스파이크, 반대 맵 관측 누락, 정합 방향 부족에 대한 계산 테스트 5개 통과. 프런트엔드 분류 테스트와 HTTP 자산 경계 테스트 통과. 실제 브라우저에서 후보 28개 전후 사진, 13개 구역 이동, 맵 표시, 모바일 폭, 기존 Rescan 12개 분류를 확인했다. 이 확인은 실제 변화 탐지 정확도 평가가 아니다.
