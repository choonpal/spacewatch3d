| 미사용 override ID/확장 필드 때문에 거부 | v1/v2 | 알려진 객체의 지원 필드만 적용, 미사용 항목은 경고. 상위 객체 파일은 변경하지 않음 |
| 모든 의미 객체를 무조건 solid로 처리 | v1 | 명시적 `solid=false`를 존중. 기존 기본값 true는 보존. 문 위 빔·아치처럼 여러 부재가 합쳐진 객체는 false로 몸 높이의 표면만 투영 가능 |

확인 플래그의 **누락**은 허용한다. 명시적 false/잘못된 타입은 확인 완료로 바꾸지 않는다. 예를 들어 입력이 직접 중력 미정렬 또는 불완전 기하라고 선언하면 지금 알고리즘이 안전한 완성 맵인 것처럼 처리하지 않는다. 이것은 새 팀 제출 조건이 아니라 지원하지 못하는 상태를 숨기지 않는 동작이다.

## 남겨둔 검사와 이유

- 유한한 숫자, 유효한 삼각형/폴리곤, 존재하는 로컬 파일, 좌표 변환의 가역성: 계산을 깨뜨리는 데이터 검사는 유지한다.
- 미터·+Z·좌표계 ID, 단일 수평 바닥의 높이/경계: 현재 거리·충돌·중앙선 계산의 전제다. 자동 단위 추측·바닥 추정·다층 기능은 구현하지 않았다. 메타데이터 확인용 true와 실제 계산 입력은 구별한다.
- 객체/구역 ID의 유일성, scene/capture 연속성, 피드백의 pose/기하 식별: 다른 객체나 다른 촬영의 결과를 잘못 결합하지 않기 위해 유지한다. 회차 간 객체 ID가 영구히 같아야 한다는 요구는 추가하지 않았다.
- 외부 정합의 성공 상태와 방향, 기준 격자 해상도·고정 위치, metric +Z SE3: 지금 기준 재사용 구현의 제한이다. 임의 행렬로 정합된 척하거나 기존 핵심 위치를 옮기지 않는다. 팀 전체 공통 계약으로 확정한 조건이 아니다.
- 샘플/격자/후보/삼각형 상한, 목표/가중치의 수치 범위, 몸 높이와 카메라 높이의 일관성: 계산 자원과 알고리즘 내부 일관성 검사다. 설정 가능하며 팀 데이터 크기의 제출 제한으로 해석하지 않는다.
- 기존 출력 폴더를 덮어쓰지 않음, 잘못된 API 최상위 타입 거부, 인라인 미지원 옵션의 조용한 무시 방지: 입력의 생산 방식과 무관한 데이터 보존/API 오용 검사다.

## 관측 의미와 반복 촬영

- 객체 관측 품질은 `가시 표면 면적 비율 × min(1, 추정 입체각 / 0.02sr)`이며 기본 관측 기준은 `>=0.35`다. 중요도가 높아도 모서리만 조금 보였다는 이유로 관측 완료가 되지 않는다. 단, 표본 기반 기하 추정이지 이미지에서 상태가 읽힌다는 보증은 아니다.
- 앞선 감사의 2번 문제는 **어느 후보에서도 기준을 못 넘는 비필수 객체가 관측 가능 분모에 포함되지 않는 것**이다. 전체 객체/전체 면적 커버리지와 관측 불가 목록은 따로 남는다. 이번 요청으로 임계값·목표·분모를 바꾸지 않았다.
- `content`는 객체 및 공간/구역을 대표하는 핵심 위치다. `transition`은 핵심 사이의 간격/연결을 채우는 이미지다. 다음 촬영에서는 안전하고 생성 가능한 content의 pose·ID·역할을 보존하고, transition을 필수 집합에서 해제한다. 필요한 이동 이미지는 연결 계산으로 다시 고른다. 같은 위치가 다시 필요하거나 관측 핵심으로 선정되는 것은 허용한다.
- 연결용으로 추가된 위치라도 해당 이미지를 빼면 선정/보완/선정 여유의 관측 목표가 깨지는 경우 content로 승격한다. 기존 핵심과 함께 목표를 보존하는 부분집합을 탐욕적으로 분류한다. `coverage_report.core_role_classification`에 승격 ID와 최종 표본 미사용을 기록한다. 이미지 장수·위치·투어 연결·실제 커버리지 점수를 바꾸는 처리는 아니며 전역 최소 핵심 수를 보장하지 않는다.
- 차단/렌더링 거부된 핵심은 억지로 보존하지 않고 사유와 원래 pose를 보고한다. 신규 구역·객체의 목표를 채우기 위한 **새 핵심 추가**도 가능하다. 과거 이미지를 새 촬영의 이미지로 재사용하지 않는다.
- `reference_reuse.viewpoint_reuse_policy`, `reference_core_count`, `released_transition_viewpoints`, `released_transition_count`로 정책과 해제를 확인할 수 있다. `reused_count`/`unavailable_count`는 이제 핵심 위치만 센다. 과거 출력은 새 필드가 없어도 검증 가능하다.

## 남는 한계

- 정확히 같은 9자리 반올림 면 키만 중복 제거한다. 다른 삼각분할의 겹침·부분 교차는 자동 정리하지 않는다.
- 공유 면은 모든 객체 의미를 남기므로 서로 다른 ID가 사실 동일 객체인 경우 의미 중요도 중복 가능성이 있다. 실제 팀 데이터에서 객체 정체성이 확인되기 전에는 임의로 병합/제거하지 않는다.
- solid 충돌은 더 보수적인 장애물 합집합이다. 누락/잘못된 라벨·잘못된 solid를 자동으로 알아맞히는 기능은 아니다.
- 중복 제거와 별도로 원본 충돌 메시를 보존하므로 중복 입력의 메모리 사용량이 증가할 수 있다. 실데이터의 전체 시간/메모리는 아직 측정하지 않았다.
- 새로운 필수 필드/카메라 관측 범위/객체 상태/이미지 가독성 조건은 실제 입력과 렌더러 결과를 받은 뒤 결정한다. 이번 검증은 합성 기하이며 게시 품질 증명이 아니다.
