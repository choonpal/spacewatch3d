# 인스턴스 분할 이후의 변화 검증 실험

확인일: 2026-10-14. 문헌 확인과 실험 제안이며, 구현·새 데이터 취득·성능 검증은 수행하지 않았다.

## 현재 데모에서 쉬워지는 부분

기존 [데모 기록](change-evidence-demo.md)에 따르면 현재 MultiChange3D 입력은 XYZRGB + `cd_type` 변화 정답 라벨이다. 연결 영역은 객체 인스턴스가 아니고, 인스턴스 ID·동일 객체 대응·원본 RGB-D·포즈가 없다. 인스턴스 분할이 있으면 맞닿은 변화 표면을 객체별로 묶고, 전후 동일 객체 후보를 비교하기 쉬워진다. 다만 **전후 인스턴스 대응과 관측 범위 확인이 별도 문제**다.

사용자가 말한 **메쉬맵에서 변화 후보를 찾고 키프레임에 연결하는 구조는 적절하다.** 전후 맵을 같은 좌표로 정합 → 변화 후보의 3D 영역/이전·이후 위치 → 해당 회차의 카메라 포즈·내부 파라미터로 투영 → 깊이와 가림을 검사한 전후 RGB 프레임 선택 순서다. 3RScan 공식 renderer도 포즈·내부 파라미터·메쉬를 이용한 RGB/깊이/인스턴스 영상과 visibility 출력을 지원한다. [공식 FAQ의 renderer 설명](https://github.com/WaldJohannaU/3RScan/blob/master/FAQ.md)

메쉬 차이는 후보를 찾는 근거이고, 실제 이동·제거의 확정 근거에는 관측 검사가 필요하다. 회차별 복원 누락이나 표면 생성 차이는 실제 공간 변화를 곧바로 뜻하지 않는다. 현재 MultiChange3D 쌍에는 원본 프레임·깊이·포즈가 없어 이 연결을 구현할 입력이 부족하다. 가까운 카메라를 고르는 것만으로 해당 변화가 보였다고 판단하지 않는다.

## 공개 데이터로 검증할 수 있는 것

- **3RScan**은 같은 환경의 여러 촬영에 걸쳐 일관된 인스턴스 ID, 장면 정합, 변화 객체별 정답 강체 변환을 제공한다. `semseg.v2.json`과 분할 PLY로 객체를 추출할 수 있고, `3RScan.json`에는 `instance_reference`, `instance_rescan`, `rigid`, `nonrigid`, `removed`, 모호성 정보가 있다. 이것은 수작업 주석을 포함한 **정답 입력**이며 자동 객체 대응의 예측 결과로 보고하면 안 된다. [공식 데이터 구조](https://github.com/WaldJohannaU/3RScan)
- **3DSSG**는 3RScan 객체의 클래스·속성·관계 정보를 추가한다. `id`는 3RScan의 장면별 객체 ID다. `global_id`는 공식 FAQ 예시에서 전역 **의미 클래스 ID**로 설명하므로, 그 이름만 보고 전후 동일 객체의 고유 ID로 쓰면 안 된다. 서로 다른 환경의 `objectId=1`도 동일 객체라는 뜻이 아니다. [공식 3DSSG 형식](https://github.com/3DSSG/3DSSG.github.io/blob/master/README.md), [3RScan FAQ](https://github.com/WaldJohannaU/3RScan/blob/master/FAQ.md)
- 단위를 먼저 정규화한다. 3RScan FAQ는 JSON 변환의 평행이동과 깊이는 mm, 3D 모델과 카메라 포즈는 m라고 설명한다. 실제 파일 버전·변환 방향·배열 저장 순서를 확인하고 공통 단위로 변환해야 한다. [공식 FAQ](https://github.com/WaldJohannaU/3RScan/blob/master/FAQ.md)

3RScan은 공식 다운로드 약관 절차를 거친 입력이 필요하다. 기존 데모의 데이터와 같은 형식으로 즉시 사용할 수 있다고 가정하지 않는다. [공식 다운로드 안내](https://waldjohannau.github.io/RIO/)

## 추천 1: 지금 입력으로 하는 작은 실험

**기존 SpaCeFormer 객체 마스크로 이동·회전·부분 관측을 함께 넣은 작은 합성 실험을 확장한다.** 새 분할 학습이 필요하지 않는다. [Task 5a 기록](../src/spacewatch3d/tasks/task_5a_change_detection/README.md)은 `scene0462_00`의 예측 객체 50개 중 3개를 제외한 복사본 47개를 비교했고, XYZ 후보·양방향 겹침·모호성 보류·일대일 할당·PCA/ICP 재비교를 이미 구현했다고 기록한다. 별도 비대칭 합성 형상의 회전·이동 검사는 있었으나, 실제 재촬영 이동 객체에 대한 검증은 없었다. 따라서 기본 매칭/ICP를 새 방법이라고 제시할 단계는 아니다.

1. 기존 실제 예측 마스크 3~5개를 선택해 알려진 평행이동·회전을 적용한 after를 만든다. 일부는 방향성 있게 점을 잘라 부분 관측을 모사하고, 비슷한 다른 객체를 방해 후보로 둔다. 완전 복사 비교보다 어려운 조건을 만들되 재촬영과 동일하다고 주장하지 않는다.
2. 기존 객체 대응 코드에 넣고 정답 대응·변환은 사후 평가에만 사용한다. 완전·부분 관측별 대응 성공률, 오매칭, 보류율, 변위/회전 오차를 비교한다.
3. 뷰어에서 동일 카메라로 전후 객체·추정 이동 화살표·정합 잔차를 확인한다. 맞춘 후 잔차가 작다는 것만으로 객체 동일성이 증명되지는 않는다.
4. 기존 PCA 초기화가 실패하는 경우에 한해 FPFH + RANSAC 초기화와 비교한다. ICP는 대략 맞춰진 초기 변환을 요구한다. [Open3D 전역 정합](https://www.open3d.org/docs/release/tutorial/pipelines/global_registration.html), [Open3D ICP](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html)

별도의 현재 MultiChange3D 뷰어에는 객체 라벨이 없으므로, 기존 변화 영역의 전후 작은 crop을 수동 지정해 정합 후보를 확인할 수 있다. 큰 연결 영역을 한 물체로 가정하지 않는다. GT 변화 라벨에서 시작하므로 변화 탐지 정확도 평가가 아니라 대응 가능성 검사다.

## 추천 2: 팀이 인스턴스 라벨을 제공할 때

점마다 `instance_id`를 갖는 전후 점군, 클래스·좌표 단위·공통 장면 정합을 받는다. 원본 점 번호와 라벨의 매핑을 보존한다. 각 촬영에서 독립 생성한 ID는 숫자가 같아도 동일 객체가 아니므로, 대응표가 없으면 크기·형태·색·클래스로 후보를 만들고 일대일 대응을 추정한 다음 객체별 강체 정합을 검증한다. 대응표가 있으면 수작업/GT 대응인지 모델 예측인지 표시한다. 대칭 물체의 회전과 원점 주변 평행이동은 해석에 주의하고, 객체 중심의 변환 전후 차이를 이동량으로 산정한다.

우선 5~10개의 명확한 객체 쌍만 선정해 기존 Task 5a 대응 코드를 실제 전후 관측에 연결하고 `그대로 / 이동 후보 / 대응 불명`을 비교한다. **팀 입력이 없으면 정식 확보한 3RScan 한 쌍의 주석 인스턴스로 같은 검증을 할 수 있다.** 정답 대응·강체 변환은 평가에만 사용하고, 예측 쪽에서 객체 ID를 익명화한다. 이 실험은 분할 학습 성능을 평가하지 않으며, 주어진 분할 이후 대응·정합 성능을 평가한다.

정답 대응을 사용한 진단 실험과 자동 대응을 사용한 본 실험을 분리하면 분할·대응·정합 중 어디서 실패하는지 확인하기 쉽다. 이는 제안한 실험 설계이며 실행된 결과는 없다.

**사라진 인스턴스 = 실제 제거**로 판정하지 않는다. 가림·미촬영·복원 누락일 수 있다. 해당 위치가 후속 촬영에서 보였고 빈 공간이었다는 깊이/카메라 근거가 없으면 `미관측 / 제거 후보`로 남긴다. 3RScan 자체도 일부 부분 스캔을 포함하며, 공식 renderer는 가림·잘림 지표를 제공한다. [공식 FAQ의 partial scans와 visibility 설명](https://github.com/WaldJohannaU/3RScan/blob/master/FAQ.md)

## 더 큰 방법의 위치

**Objects Can Move (ECCV 2022)**는 깊이 차이로 초기 변화 영역을 만든 뒤, 전후 대응의 강체 변환 일관성과 그래프 최적화로 객체를 발견한다. 공식 코드에는 정합된 메쉬, 깊이 렌더링, supervoxel, 특징 추출 등의 준비가 있어 현재 PLY 두 개만으로 동일 파이프라인을 재현하는 작업은 작지 않다. 우선 기존 객체 마스크 실험을 실제 관측 차이가 있는 조건으로 확장한 뒤 검토할 가치가 있다. [공식 논문](https://arxiv.org/abs/2208.09870), [공식 코드](https://github.com/katadam/ObjectsCanMove)
