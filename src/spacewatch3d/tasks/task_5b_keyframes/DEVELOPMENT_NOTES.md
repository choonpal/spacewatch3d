# Task5b 개선 작업 메모

객체별 3D 메시와 메타데이터에서 중앙 경로와 360도 키프레임 위치를 선정한다. 서버가 3D 맵을 처리하고, 사용자에게는 선정 위치의 파노라마를 제공한다. 실제 이미지 합성은 별도 파트다.

## 유지할 결정

- 벽과 천장은 `structures`로 전달하고 공간 커버리지로만 평가한다. `objects`의 wall과 ceiling 등 명시적 이름도 구조물로 처리한다. 객체 중요도나 LLM 점수를 추가하지 않는다.
- 환풍구 등은 별도 객체 ID와 메시가 있어야 객체 중요도를 적용한다. 가시성은 높이와 가림을 포함한 3D 계산이며, 평면도는 표시 방식일 뿐이다.
- 중앙 경로는 확인된 단일 수평 바닥에서 만든다. 카메라 높이는 건물 크기에 비례시키지 않고 촬영 조건을 따른다.
- LLM은 중요도 제공자만 추후 연결한다. 지금은 수동 점수와 기본값을 유지한다.
- Task5b와 전용 테스트만 수정한다. 공통 계약과 다른 task는 변경하지 않는다. GitHub 커밋과 업로드는 별도 명시 요청 없이는 하지 않는다.

## 작업 순서

1. [x] 적응형 후보 배치: 분기와 좁은 구간을 보강하고, 인접 후보의 가시성 변화가 큰 구간을 한 번 더 탐색한다. 보강 간격은 격자 해상도 이상이고 분기와 끝점은 보존한다. `candidate_report`에 원인을 기록한다.
2. [x] 촬영 높이 입력: 명시 설정, `camera.height_above_floor_m`, 경고를 남기는 임시 1.5m 순으로 적용하고 출처를 기록한다. 건물 크기에 비례시키지 않는다.
3. [x] 전체 이미지 수 고려: 이동용 이미지까지 포함한 추가 정보량과 추가 장수로 선정한다. 목표를 보존하는 제거와 단일 교환을 적용하며 전역 최소 장수를 보장하지 않는다.
4. [x] 회귀 검증: 천장과 높은 객체의 가림, 구조물의 의미 점수 제외, 적응형 후보, 높이 우선순위, 이동용 장수와 필수 객체 조건을 시험한다. 밀도와 선정 비교는 같은 표면 표본과 공통 분모를 사용한다.
5. [x] 교환 후 재제거: 단일 교환 뒤에도 연결·이동용 이미지를 다시 계산하며 제거 가능한 핵심 위치가 없어질 때까지 정리한다. 필수 객체·공간 목표·연결 조건과 이미지 장수 비증가를 지킨다.
6. [x] 독립 사각지대 검사: 미평가 유효 경로 노드를 모두 검사해 샘플 가시 표면 합집합과 객체별 최고 품질을 보존하는 위치를 승격한다. 양 끝·정중앙이 안 보여도 탐색하고, 실제 발견은 거리 솎기를 우회한다. 거부된 위치는 기준과 탐색 모두에서 제외한다. `max_visibility_probes=2000` 또는 후보 상한 초과 시 조용히 생략하지 않고 오류를 낸다.
7. [x] 연결 우회: 최단 경로의 이미지 간격 조건이 실패하면, 점수 계산된 유효 후보의 hop 네트워크에서 대체 연결을 찾는다. hop 수·거리 순으로 탐색하고 실제 그래프 폴리라인만 사용한다. 거부 이미지·미평가 위치를 넣거나 분리 공간을 순간 이동으로 잇지 않는다. 카메라 거부는 통행 금지가 아니므로 실제 장애물은 입력 기하에 반영한다.
8. [x] 가중치와 목표 분리: 효용 증가량이 없으면 미달 목표 수/부족량이 개선되는 후보로 진행한다. 가중치 0이어도 공간·구역·객체 목표와 필수 객체는 유지한다. 최종 이동용 이미지까지 평가하고 `constraint_progress` 선정 사유를 남긴다.
9. [x] 연결 가능성 우선: 단일 교환은 유효 연결을 이미지 장수보다 우선한다. 실패가 남으면 전체 유효 카메라 hop 성분마다 원래 전역 목표를 검사하고 역제거로 대안을 만든다. 여러 위치 교체도 처리하며 기준 필수 위치와 원래 관측 분모를 버려 성공시키지 않는다.
10. [x] 연결용 후보 보존: 독립 검사에서 새 정보가 없어도 후보 간 dense 카메라 hop 연결에 필요한 위치를 승격한다. 거부 이미지를 승격하지 않고 실제 분리 성분을 억지로 잇지 않는다. 추가 위치도 점수와 장수·자원 상한에 포함한다.
11. [x] 기준 경로·키프레임 재사용: 완료 계획만 `reference_route.json`을 저장한다. 외부 성공 정합 또는 생산자가 확인한 공통 좌표계를 사용하고, 현재 바닥/구조/객체/구역을 모두 기준 좌표에 맞춘다. 안전한 기존 위치·ID·pose·역할을 유지하고 새 중앙선으로 스냅하지 않는다. 장애물/렌더러 거부는 사유와 원래 pose를 남기고 현재 목표에 필요한 위치를 추가한다. 경로 ID 계보와 버전·비교 가능 상태를 분리한다. 과거 이미지는 새 촬영 이미지로 재사용하지 않는다.
12. [ ] 후속: 정보 손실을 검사하는 가지 정리와 충돌 재검사 기반 평활화, 실제 맵과 같은 장수 비교 실험, 합성 가능 후보 제한, 실제 입력·외부 정합 연결 검증, 게시용 exporter.

## 완료 판단과 주의사항

- 후보를 늘린 후 관측 가능한 표면 분모를 고정하고 선정한다. 관측 가능 표면 기준과 입력 전체 표면 기준 커버리지를 모두 기록한다.
- 벽을 관통하는 연결, 분리 공간 순간 이동, 필수 객체 누락을 성공으로 처리하지 않는다.
- 후보 밀도와 표면 샘플 수 모두 근사 정확도에 영향을 준다. 합성 맵 통과를 실제 이미지 품질 검증으로 표현하지 않는다.
- 효용 가중치 0은 순위 점수만 끈다. 해당 커버리지 목표를 끄려면 `*_target=0`을 별도 지정하고, 필수 객체는 `must_see`를 별도 해제해야 한다. 우회나 목표 보완도 전역 최적 장수/방문 순서를 보장하지 않는다.
- 독립 검사는 경로의 격자 노드와 고정 샘플만 보장한다. 노드 사이의 짧은 시야·샘플에 없는 표면·후보 간 최적 공동 관측 조합은 보장하지 않는다. 서버 계산량은 늘지만 검사한 모든 위치를 사용자 이미지로 보내지는 않는다.
- 합성 가능 범위는 렌더러 파트의 입력이 필요하다. LLM 연결과 자동 정합, 실제 이미지 합성은 이번 수정에서 구현하지 않는다.
- 기준 재사용의 입력은 CLI `--reference-route` / `--registration`이다. 장면 인라인 필드나 Task5a 공통 manifest 직접 연결은 미지원이다. 서로 다른 회차·올바른 scene/frame ID·같은 격자·metric +Z 보존 SE3를 검증한다. 기준 가상 카메라의 절대 높이를 유지하며 현재 촬영 카메라 높이와 구별한다. 렌더 요청에 현재→기준 변환과 경로 버전을 전달한다.

## 현재 상태

- 기존 기준 예시: 후보 35개, 핵심 3개와 이동용 6개, 총 9개 이미지 위치. 실제 이미지는 없음.
- v2 개선 예시: 후보 123개. 기본 구역 균형 공간 목표 90%에서는 위치 2개, 관측 가능 표면 90.56%; 목표를 전체 균형과 구역별 99%로 올리면 위치 7개, 관측 가능 표면 99.38%. 이전 9개 위치의 99.42%와 구별한다. 두 개선 실행 모두 관측 가능한 객체 중요도 조건과 필수 객체 조건을 만족했다.
- 비교 도구: `examples/compare_planning.py`. 모든 경로 노드와 동일 표면 샘플 600개를 공통 기준으로 삼았다. 밀도와 선정 방식의 비교이며 같은 장수 비교나 실제 이미지 품질 검증은 아니다.
- v4 검증: 전용 91개와 공통 19개, 총 110개 테스트. v3의 5→2개 중복 정리·좁은 창 사각지대 회귀 검사를 유지했다. 새로 이미지 위치 3개 우회와 여러 hop 우회, 무작위 격자 40개의 독립 연결 가능성 비교, 가중치 0의 공간/구역/객체 목표, 미달 목표의 부분 진전, 임계값 경계, 피드백·생성 요청·선정 사유를 검사한다. 실제 촬영 데이터와 이미지 품질은 아직 미검증이다.
- v4 두 공간 예시: 남은 경로 노드 12개를 독립 검사했고 추가 승격 없이 v2·v3와 동일한 123개 후보·2개/7개 이미지 위치를 유지했다. 기본/99% 목표 실행은 약 7.0초/7.2초였다. 모든 유효 경로 노드의 샘플 관측 정보를 후보 집합이 이미 포함했음을 확인한 결과다.
- v4에서도 기존 OBJ와 GLB 합성 맵 4개를 재검증했다. v3와 같이 연결된 3개는 완료(이미지 위치 3·3·5개), 분리 공간 1개는 `disconnected_tour` 미완료였다. 각 맵에서 남은 노드 25·21·11·44개를 검사했고 분리 공간에서 후보 1개를 추가했다. 입력 파일은 보존됐고 중앙선 그래프는 이전의 독립 충돌 검사 결과와 동일했다. 이 4개에는 렌더링 거부 피드백이 없으므로 우회 기능 자체의 증거는 전용 합성 경로 테스트다. 분리 공간의 전체 투어 불가능 문제는 이번 변경으로 해결됐다고 표시하지 않는다.
- v2 계산 비용: 이 작은 예시에서 기존 약 1.8초, 개선 약 6.4초였다. 후보 증가와 v3 독립 검사로 서버 계산은 늘며 이미지 수 감소와 별개다. 처리 시간은 실행 환경에 의존한다.
- v5 검증: 전용 117개와 공통 19개, 총 136개 테스트. 연결 실패 2장→유효 3장, 여러 위치 동시 대체, 정보 증가가 없는 연결용 후보 보존, 독립 무작위 연결 비교 40개, 기준 pose/ID/역할·방향·높이 유지, 외부 변환·거부 검사, 차단/생성 거부·세 번째 촬영 재사용·입력 보존·CLI를 포함한다. 실제 정합이나 이미지 생성은 수행하지 않았다.
- v5 두 공간 99% 목표 반복 예시: 첫 회차 위치 7개·관측 가능 커버리지 99.38%, 동일 기하 다음 회차에서 7개 전부 유지·추가 없음·같은 버전과 커버리지였다. 한 위치 차단 시 6개 유지·1개 사용 불가·8개 추가(총 14개), 버전 2·관측 가능 커버리지 99.37%였다. 위치 비교 가능 여부는 `partial_reference_views`로 보고했다. 새 물체/연결과 기준 위치 보존을 함께 고려하므로 차단 후 장수가 증가할 수 있으며 전역 최적 장수는 보장하지 않는다.
- v5에서도 기존 OBJ/GLB 합성 맵 4개를 다시 검사했다. 연결된 3개는 이전과 같은 이미지 위치 3·3·5개로 완료, 분리 공간은 18개·`disconnected_tour` 미완료였다. 입력 파일 해시는 보존됐고 그래프는 이전 독립 충돌 검사 기준과 동일했다. 기준 위치를 현재 경로에 붙이는 새 경로도 차단 예시에서 별도 기하 검사로 바닥 여유 거리와 장애물 비충돌을 확인했다.
- 다음 작업: 항목 12. 가지를 짧다는 이유만으로 제거하지 말고, 가시성이나 필수 객체 손실을 검사한 뒤 적용한다. 외부 렌더러 관측 범위와 실제 팀 맵이 필요한 작업은 입력 계약부터 확인한다. v5 수정은 항목 9·10·11이며 정합 알고리즘·이미지 합성·공통 계약은 변경하지 않았다.
