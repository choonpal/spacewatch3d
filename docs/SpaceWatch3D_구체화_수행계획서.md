# SpaceWatch3D 계획발표 및 구체화 수행계획서

> 과제명: 3차원 가상투어 생성 자동화 기반의 시계열 공간 변화 모니터링 기술개발
>
> 참여기업: ㈜뉴딕스 / 개발팀: SpaceWatch3D
>
> 개정일: 2026-09-14
>
> 최신 main `c52be096`의 계획서를 바탕으로 kdj `fbe9dd17`의 구현 결과와 후속 계획을 반영했다. 현재 완료된 복원 실험과 앞으로 개발할 기능을 구분한다. 웹·투어 통합 및 변화 비교의 세부 구성은 팀의 구현 제안이며, kdj에서 모두 구현되었다는 의미가 아니다.

## 1. 과제 목적 및 필요성

디지털트윈을 시설 관리에 활용하려면 공간의 형태를 한 번 복원하는 데서 나아가, 공간 안에 무엇이 있고 시간이 지나며 어떻게 달라졌는지 기록해야 한다. 사진과 영상만 날짜별로 보관하면 촬영 위치와 방향이 달라졌을 때 같은 구역을 다시 찾고 물품 배치 변화를 확인하는 데 수작업이 필요하다. 반대로 좌표와 색상만 가진 3D 점군은 공간 형태를 표현하지만, 각 점이 벽·바닥·의자 중 무엇에 해당하는지 직접 설명하지 못한다.

본 과제는 영상에서 복원한 3D 점군에 이미지 분할로 얻은 클래스와 관측 근거를 연결하여 **의미 지도(semantic map)**를 구축한다. 이후 서로 다른 촬영 회차의 지도를 공통 좌표계에 맞춰 변화 후보를 찾고, 원본 영상으로 근거를 확인할 수 있게 한다. 카메라 자세와 대표 장면을 활용한 가상투어 및 웹 이력 조회를 함께 제공하여 기록·탐색·점검을 연결한다.

### 최종 목표

- 촬영별로 위치·색상·클래스·신뢰도·관측 근거를 가진 3D 의미 지도를 생성한다.
- 대표 장면과 실제 이동 관계를 연결한 가상투어를 제공한다.
- 재촬영 결과를 기준 좌표계에 정합하고, 공통 관측 구역의 변화 후보와 근거를 제공한다.
- 웹에서 공간·촬영 날짜 선택, 투어 탐색, 의미 지도 조회, 전후 비교와 처리 상태 확인이 가능한 프로토타입을 구현한다.
- 초기 RGB 영상에서 처리 흐름을 검증한 뒤, 360° 카메라 입력으로 확장한다.

## 2. 현재 구현 상태와 범위

### 2.1 kdj에서 완료한 범위

현재 검증 경로는 **RGB 영상 → FFmpeg 프레임 추출 → COLMAP SfM → 렌즈 왜곡 보정 → OpenMVS 깊이 추정·조밀 복원**이다. 실시간 SLAM 시스템으로 구현된 것은 아니다. SfM은 여러 이미지의 대응으로 카메라 자세와 3D 구조를 복원하며, MVS는 복원된 카메라와 여러 이미지로 깊이 및 조밀 점군을 생성한다.

| 항목 | 확인된 결과 |
|---|---|
| 시험 데이터 | TUM freiburg1_xyz의 RGB 영상 |
| 프레임 추출 | 5fps, PNG 133장 |
| 실행 환경 | Ubuntu 22.04.5 LTS, COLMAP 3.7, OpenMVS 2.4.0, CPU 8스레드 |
| SfM | 단일 모델에 133/133장 등록, 희소점 11,994개 |
| 평균 재투영 오차 | 1.373034px |
| 보정 이미지·깊이 지도 | 631×473, 각각 133개 |
| 조밀 점군 | 252,564개 |
| OpenMVS 실행 시간 | 약 507.24초, 8분 27초 |

TUM의 깊이 센서 데이터와 정답 궤적을 복원 입력으로 사용하지 않았다. 좌표와 깊이는 임의 스케일이며, 정답 대비 거리·자세·깊이 정확도는 아직 평가하지 않았다. 등록률·점 수·유효 깊이 비율을 정확도 점수로 해석하지 않는다. 메시·텍스처·3D Gaussian Splatting 결과는 생성하지 않았다.

### 2.2 구현할 범위와 제안의 구분

| 구분 | 내용 |
|---|---|
| kdj의 다음 구현 계획 | 점군 품질 확인·후처리, 프레임·카메라·깊이 ID 연결, 2D segmentation, 2D–3D 관측 연결, 다중시점 라벨 통합, 의미 지도 저장·평가 |
| kdj의 이후 확장 방향 | VLM 기반 클래스 후보 확장, 촬영 회차 간 스케일·좌표 정합과 변화 비교, 360° 입력 |
| 팀 목표를 연결한 구성안 | 키프레임·가상투어, 웹 API·저장소·날짜별 조회, 의미 지도 기반 변화 후보와 원본 관측 확인 |
| 아직 확정하지 않은 세부 사항 | segmentation 모델, 라벨 통합 가중치, 정합 알고리즘·임계값, 변화 비교 단위·알고리즘, 웹 세부 스택 |

### 2.3 의미 지도와 메타데이터

**기하 정보를 가진 3D 맵을 먼저 복원하고, 2D segmentation으로 의미 정보를 추가해 semantic map으로 확장한다.** 이미지의 클래스만으로 3D 좌표가 생기는 것은 아니다.

| 정보 | 생성 단계 | 예시 |
|---|---|---|
| 촬영·관리 정보 | 입력 저장·프레임 추출 | 세션 ID, 프레임 ID, 촬영 시각, 영상 내 상대 시각 |
| 기하·관측 정보 | SfM·MVS | 카메라 내부 파라미터, 자세, xyz, rgb, 깊이, 관측 연결 |
| 의미 정보 | 2D 분할·관측 연결·통합 | class_id, 신뢰도, 관측 수, 근거 프레임 |
| 변화·이력 정보 | 회차 정합·비교 | 기준 지도 버전, 좌표 변환, 변화 후보, 판단 상태 |

“메타데이터가 부족해서 segmentation을 한다”는 표현은 **복원 결과에 없는 의미 정보를 추가한다**는 뜻으로 사용한다. 점별 클래스와 관측 정보는 의미 지도의 핵심 데이터다. 모든 점을 강제로 분류하지 않으며 관측 부족·분류 충돌은 `unknown`으로 보존한다. `class_id`는 객체 종류이며, 개별 의자의 고유 ID인 `instance_id`와 다르다.

## 3. 전체 실행 순서와 분기

```text
촬영 회차 A 또는 B
  1. 원본·세션 정보 저장 → 프레임 추출
  2. COLMAP SfM → 카메라 자세·희소 점군
     ├─ 3. 렌즈 왜곡 보정 → OpenMVS 깊이·조밀 점군
     │     → 4. 점군 품질 확인·프레임/카메라/깊이 연결
     │     → 5. 보정 이미지의 2D segmentation
     │     → 6. 3D 점을 이미지에 투영하고 깊이로 가시성 확인
     │     → 7. 여러 시점의 클래스를 통합 → 회차별 의미 지도
     └─ 별도 경로: 대표 장면 선별 → 이동 링크 → 회차별 가상투어

서로 다른 촬영 회차 A와 B가 확보된 뒤
  8. 기준 지도 지정 → 스케일·좌표 정합 → 공통 관측 구역 확인
  9. 의미·위치의 변화 후보 생성 → 원본 2D 관측으로 근거 확인
 10. 웹에서 날짜별 투어·의미 지도·변화 및 처리 이력 조회
```

의미 지도 생성에는 한 회차의 여러 이미지가 필요하고, 시계열 변화 비교에는 최소 두 회차가 필요하다. 가상투어는 SfM 자세와 대표 프레임으로 개발할 수 있으므로 조밀 복원이나 의미 지도 완성을 기다릴 필요가 없다. 웹도 샘플 데이터로 병렬 개발한다.

## 4. 단계별 수행방법과 완료 기준

### 1단계. 원본 저장과 프레임 추출

- **입력:** RGB 영상, 공간·세션 ID, 촬영 시각, 카메라 정보.
- **처리:** 원본을 보존하고 프레임·영상 내 상대 시각·파일 경로를 연결한다. 초기 기준선은 현재 실험의 5fps 균일 추출이다.
- **출력:** 원본 목록과 프레임 메타데이터.
- **완료 기준:** 모든 파생 프레임에서 원본 영상과 해당 위치를 찾을 수 있다.

현재 AVI의 상대 시각과 TUM 원본 센서 타임스탬프를 동일시하지 않는다. 360° 확장 시 파노라마를 여러 방향의 일반 시야각 이미지로 변환하고 원본 프레임·시야 방향·카메라 모델의 대응을 보존한다.

### 2단계. SfM으로 카메라 자세와 희소 지도 복원

- **입력:** 프레임과 카메라 모델.
- **처리:** 특징점 추출·매칭, 기하 검증, 삼각측량과 번들 조정으로 카메라 및 희소 구조를 복원한다.
- **출력:** 카메라 내부 파라미터·자세, 희소점, 2D–3D 트랙, 등록 상태.
- **완료 기준:** 등록·미등록 이미지를 식별하고, 모델 연결성·재투영 오차·카메라 경로를 점검한다.

자세는 월드→카메라 변환으로 저장하며 카메라 중심은 `C = -Rᵀt`로 계산한다. 단안 복원의 크기를 미터로 단정하지 않는다. 의미 클래스는 이 단계에서 생성되지 않는다.

### 3단계. 왜곡 보정과 MVS 조밀 복원

- **입력:** SfM 카메라·희소 모델과 RGB 이미지.
- **처리:** 렌즈 왜곡을 보정하고 OpenMVS 형식으로 변환한 뒤 다중시점 깊이 추정·일관성 검사·깊이 통합을 수행한다.
- **출력:** 보정 이미지, 대응 PINHOLE 카메라, 깊이 지도, 조밀 점군, 관측 정보를 가진 작업 모델.
- **완료 기준:** 모델 재로딩, 이미지·깊이 참조, 좌표·깊이 유효성 및 빈 영역·잡음을 확인한다.

`scene_dense.ply`만 저장하면 카메라·점별 관측 근거가 부족하므로 `scene_dense.mvs`, 보정 이미지, 카메라와 깊이 지도를 함께 보관한다. 메시·텍스처 생성은 의미 지도 구축의 필수 단계가 아니다.

### 4단계. 점군 품질과 데이터 대응 정리

- **입력:** 조밀 점군과 카메라·이미지·깊이 파일.
- **처리:** 빈 영역과 고립점을 확인하고 필요한 경우 이상점 제거·voxel downsampling을 적용한다. 원본을 보존하며 원본 점과 후처리 점의 대응을 기록한다.
- **출력:** 지도 버전, 후처리 기록, 프레임·COLMAP image ID·OpenMVS image ID·깊이 파일·시각의 대응표.
- **완료 기준:** 특정 점의 근거 이미지와 카메라·깊이를 역추적할 수 있다.

깊이 파일의 번호를 프레임 파일명의 번호와 같다고 가정하지 않는다. 다운샘플링으로 여러 점이 합쳐지면 단일 ID를 임의로 대입하지 않고 원본 점 집합과의 관계를 보존한다.

### 5단계. 2D segmentation으로 의미 정보 생성

- **입력:** 보정 이미지와 공통 클래스 목록.
- **처리:** 초기에는 천장·벽·바닥·의자 등 고정 클래스 분할 모델을 선정·검증한다.
- **출력:** 이미지별 클래스 마스크, 제공 가능한 신뢰도, 모델·클래스 목록 버전.
- **완료 기준:** 분할 결과가 원래 보정 이미지 좌표와 정확히 대응하고 대표 이미지의 수작업 정답으로 오류를 확인한다.

현재 실험의 보정 해상도는 631×473이다. 추론 과정에서 크기 변경·잘라내기·패딩을 적용했다면 그 변환을 되돌려야 한다. 원본 640×480 이미지의 마스크나 내부 파라미터를 보정 좌표와 섞지 않는다. VLM 클래스 후보 추출은 고정 클래스 의미 지도를 검증한 뒤 확장한다.

### 6단계. 3D 점과 2D 분할 결과 연결

- **입력:** 3D 점, 보정 카메라의 K·R·t, 같은 이미지의 깊이와 클래스 마스크.
- **처리:** 3D 점이 보정 이미지의 어느 화소에 보이는지 투영하고 가시성을 검증한 뒤 그 화소의 클래스 후보를 점에 연결한다.
- **출력:** 점–프레임–화소–클래스 후보–신뢰도–가시성 근거의 관측 기록.
- **완료 기준:** 이미지 밖·카메라 뒤·다른 표면에 가려진 점에 해당 프레임의 라벨이 잘못 전달되지 않는다.

```text
Xc = R · Xw + t
u = fx · Xc.x / Xc.z + cx
v = fy · Xc.y / Xc.z + cy

확인: Xc.z > 0, (u,v)가 화면 내부,
      깊이 지도가 유효하며 투영 깊이와 허용 오차 안에서 일치
```

**기하 연산의 방향은 3D 점 → 2D 화소이고, 의미 정보 전달은 2D 분할 결과 → 3D 점이다.** 깊이 형식·해상도·좌표계를 확인한 뒤 같은 정의의 깊이를 비교한다. 화면 안에 투영된다는 사실만으로 실제 보이는 점이라고 판정하지 않는다.

### 7단계. 다중시점 라벨 통합과 의미 지도 저장

- **입력:** 같은 점에 연결된 여러 프레임의 클래스 후보와 관측 근거.
- **처리:** 분할 신뢰도, 관측 수, 시점 등을 고려해 클래스를 집계한다. 거의 같은 연속 프레임이 반복 투표해 신뢰도가 과대해지지 않도록 비교 실험한다.
- **출력:** `point_id`, `xyz`, `rgb`, `class_id`, 신뢰도, 관측 수, 근거 프레임·시각을 가진 의미 지도.
- **완료 기준:** 클래스별 색상 표시, 원본 이미지 재투영, 수작업 정답 일부와의 비교로 의미 연결의 정확도를 검증한다.

통합 방식과 임계값은 실험으로 선정한다. 관측 부족·충돌은 `unknown`으로 남긴다. 의미 지도는 모든 표면이 빠짐없이 복원된 완전한 공간 모델을 뜻하지 않는다.

### 별도 경로. 키프레임 선별과 가상투어

- **입력:** SfM 자세·프레임, 품질·관측 중첩 정보.
- **처리:** 중복도·선명도·새 관측 영역·주요 구역 커버리지로 대표 장면을 고르고, 촬영 경로와 관측 근거로 이동 링크를 만든다.
- **출력:** 대표 프레임, 선택 이유, 투어 그래프, 화면 이동 방향.
- **완료 기준:** 장면 수를 줄이면서 주요 구역을 유지하고 벽 너머 잘못된 이동 링크를 만들지 않는다.

중복 프레임은 추가 관측 정보가 적은 이미지이며, 같은 방의 모든 이미지를 뜻하지 않는다. 현재 5fps 추출은 자동 키프레임 선별 완료가 아니다. 복원·의미 통합·투어의 프레임 선택은 목적별로 관리하고 원본을 삭제하지 않는다. RGB 단계에서는 대표 이미지 탐색을 검증하고 360° 입력이 확보되면 파노라마 뷰어와 연결한다.

### 8단계. 재촬영과 세션 간 공간 정합

- **입력:** 서로 다른 회차 A/B의 지도·카메라·이미지·관측 정보.
- **처리:** B도 독립적으로 복원·의미화한다. 기준 맵 A의 ID·버전을 고정하고, 안정적인 구조의 대응으로 B→A 변환을 추정한다.
- **출력:** 정합 변환, 검증 근거, 공통 관측 범위와 성공·실패 상태.
- **완료 기준:** 같은 실제 장소가 공통 좌표계에서 일관되게 대응하고 미관측 영역을 구분한다.

임의 스케일 지도 간에는 `X_A = s R X_B + t` 형태의 Sim(3)을 검토한다. 실제 스케일이 이미 일치하면 SE(3)을 검토한다. 촬영 경로와 순서를 같게 강제하는 작업이 아니며 촬영 날짜는 그대로 유지한다. 움직인 물체에 맞춰 배경을 왜곡하지 않는다. 구체적인 정합 방식은 후속 실험으로 선정한다.

### 9단계. 의미 지도 기반 변화 후보와 근거 확인

- **입력:** 정합된 A/B 의미 지도, 공통 관측·깊이 정보, 원본 이미지.
- **검증안:** 3D 위치·클래스의 차이로 후보 영역을 찾고, 대응하는 원본 2D 관측에서 추가·제거·재배치 근거를 확인한다.
- **출력:** 변화 후보 영역·유형·신뢰 정보·근거 프레임·판단 상태.
- **완료 기준:** 실제 변화와 조명·가림·복원 누락·분할 오류를 구분하여 평가한다.

이 단계의 비교 단위는 점·voxel·클러스터·객체 중 아직 확정하지 않았다. 서로 독립 복원한 점군의 점 ID는 같은 물체의 대응 ID가 아니므로 점별 일대일 차감으로 판단하지 않는다. 점군 밀도 차이도 실제 변화와 구분한다. `class_id`가 같다는 이유만으로 동일 객체나 이동을 확정할 수 없다.

한쪽에서 점이나 객체가 없다는 이유만으로 제거를 확정하지 않는다. 양쪽 촬영에서 실제 관측 가능한 구역인지 확인하고, 관측 부족·정합 실패·모호한 객체 대응은 판단 보류로 남긴다. 영상 차이 방식은 비교 기준선으로 활용할 수 있지만, 최종 알고리즘이 확정된 것은 아니다.

### 10단계. 웹·저장·이력 조회

- **입력:** 회차별 투어·의미 지도, 정합·변화 결과와 처리 상태.
- **처리:** 업로드·분석 실행·진행 조회 API, 공간·날짜별 탐색, 변화 근거 조회를 연결한다.
- **출력:** 통합 웹 프로토타입과 버전별 분석 이력.
- **완료 기준:** 변화 후보에서 해당 원본 프레임과 지도 버전까지 찾아갈 수 있다.

웹 클라이언트 → API 서버 → 분석 모듈의 실행 요청과 역방향 상태·결과 응답을 구분한다. 파일 저장소는 영상·깊이·점군·마스크를 보관하고, 메타데이터 DB는 ID·경로·클래스 규격·관측 참조·작업 상태·정합·변화 이력을 관리한다. 대규모 점별 관측은 별도 파일이나 테이블로 분리할 수 있으며 저장 방식은 규모에 맞춰 결정한다.

## 5. 데이터 규격과 실패 처리

아래 필드는 모듈 간 연결을 위한 제안 규격이며 최종 저장 스키마는 팀 합의로 확정한다.

| 데이터 | 필수 정보 |
|---|---|
| 세션·프레임 | scene_id, session_id, frame_id, 원본 경로, 촬영 시각·시간대, 영상 내 상대 시각 |
| 보정 카메라 | camera_id, image ID 대응, K, 월드→카메라 R·t, 해상도, 투영·보정 버전 |
| 기하 지도 | map_id·version, point_id, xyz·rgb, 스케일 상태, 원본 모델·후처리 대응 |
| 깊이 | 이미지·깊이 ID 대응, 파일 경로, 깊이 정의, 해상도, 유효 상태 |
| 2D 분할 | frame_id, 마스크·신뢰도 경로, 모델·클래스 목록 버전, 추론 좌표 변환 |
| 관측 | 지도점 ID, frame_id, 투영 화소, 깊이 일치·가시성, 클래스 후보·신뢰도 |
| 의미 지도 | 지도 버전, 점별 클래스·신뢰도·관측 수, 근거 관측 참조, unknown 상태 |
| 투어 | 대표 프레임, 선택 이유, 이동 링크, 표시 방향 |
| 정합 | 기준·대상 지도 버전, 대상→기준 변환, 스케일, 검증 근거·상태 |
| 변화 | 비교 회차·지도 버전, 영역·유형, 관측 근거, 알고리즘 버전·판단 상태 |

같은 클래스의 ID가 회차마다 달라지지 않도록 클래스 목록을 버전 관리한다. 지도를 후처리·재복원하면 새 버전을 만들고 기존 분석이 참조한 버전을 유지한다. 길이 기준이 확보된 경우에만 미터 단위로 보고한다.

상태는 최소한 `미등록 프레임`, `복원 실패`, `무효 깊이`, `의미 미확정`, `정합 실패`, `공통 관측 부족`, `변화 판단 보류`를 구분한다. 이 상태를 정상적인 ‘변화 없음’에 포함하지 않는다.

## 6. 5인 병렬 개발과 담당자

모듈은 독립 실행 단위이며 ROS 사용을 전제하지 않는다. 각 담당자는 코드·검증·문서·담당 발표 내용을 함께 작성한다.

| 담당 | 주 책임 | 입출력 | 병렬 개발 방법 |
|---|---|---|---|
| 김동주 | SfM·MVS 공간 복원 | RGB → 자세·점군·깊이·원본 모델 | 현재 TUM 결과로 복원 품질·재현성 검증 |
| 이태훈 | 키프레임·투어 | 프레임·자세 → 대표 장면·이동 링크 | 현재 SfM 자세와 프레임으로 시작 |
| 임현우 | 2D–3D 관측 연결·회차 정합 | 카메라·깊이·점군·마스크 → 관측 대응·정합 변환 | 작은 정답 마스크와 알려진 좌표 변환으로 연결 검증 |
| 서관우 | 의미·변화 분석 | 이미지·관측 → 분할·라벨 통합·변화 후보 | 2D 분할부터 시작하고 샘플 관측으로 통합 개발 |
| 시한결 | 웹·서비스 통합 | 모듈 결과 → 저장·API·조회·시각화 | 샘플 지도·투어·변화 JSON으로 화면과 API 개발 |

웹·서비스는 공통 작업으로 두며 시한결과 서관우가 함께 참여한다. 시한결은 서비스 통합을, 서관우는 의미·변화 결과 연결을 중심으로 담당한다. 역할은 임의로 배정한 초안이며, 진행 상황과 팀 협의에 따라 유동적으로 변경됩니다.

임현우가 관측 대응을, 서관우가 클래스 예측·통합을 담당하므로 `점–프레임–화소–가시성` 규격을 먼저 맞춘다. 실제 출력이 나오기 전에도 버전이 표시된 샘플 입출력으로 통합한다. 발표자료 취합과 발표 순서는 팀 회의에서 정한다.

## 8. 요구사항과 검증 계획

우선 검증할 질문은 **“보이는 3D 점에 올바른 2D 클래스가 연결되어, 여러 관측을 통합한 의미 지도를 신뢰할 수 있는가?”**이다. 의미 지도를 먼저 검증한 뒤 반복 촬영의 정합과 변화 판정을 평가한다.

| 요구·시험 | 평가 내용 |
|---|---|
| 기하 복원 재현 | 등록 이미지 수, 모델 연결성, 재투영 오차, 깊이 유효성, 처리 시간 |
| 2D 의미 분할 | 수작업 정답 일부의 클래스별 IoU·오분류; 모델별 조건 고정 |
| 2D–3D 연결 | 직접 표시한 점의 화소 대응, 뒤쪽·가려진 점 제외, 깊이 일치 |
| 의미 지도 | 수작업 라벨 일부의 클래스별 정확도/IoU, unknown 비율, 잘못 연결된 라벨 |
| 다중시점 통합 | 단일 관측·다수결·신뢰도 고려 방식 비교, 중복 프레임 영향 |
| 키프레임·투어 | 동일 프레임 예산에서 커버리지·중복도·잘못된 이동 링크 |
| 회차 정합 | 안정 구조 대응, 좌표·스케일 일관성, 정합 성공·실패 비율 |
| 변화 비교 | 추가·제거·재배치 후보의 정밀도·재현율·F1, 무변화 오탐률 |
| 서비스 통합 | 업로드→결과→원본 근거 조회, 날짜 선택, 실패 상태 표시 |

변화 없음, 반대 촬영 경로, 조명만 변화, 물체 추가·제거, 가림·일부 미촬영, 비슷한 다른 방을 포함한다. 서로 다른 회차의 정답은 별도로 확보한다. 수치 목표·깊이 허용 오차·클래스 목록은 초기 데이터와 멘토 요구에 맞춰 확정한다. 미터 단위 정확도에는 별도 스케일·정답이 필요하다.

논문 연구 질문 후보는 관측 가시성 검사·다중시점 라벨 통합·대표 프레임 선별이 의미 지도의 정확도와 처리 비용에 주는 영향이다. 변화 비교까지 포함할지는 의미 지도 검증 결과와 지도교수 협의를 통해 결정한다.

### 회의 운영

- 팀 정기회의는 **매주 화요일 주 1회** 진행할 예정이다. 시각과 방식은 팀 협의로 정한다.
- 멘토 회의는 화요일 회의에 연계하는 안을 우선 조율하고, 참석이 어려우면 별도 일정을 정한다. 실제 수업·사업의 회의 요건을 확인해 충족한다.
- 회의 전 GitHub Issue에 결과·실패 사례·질문을 공유하고, 회의 후 결정·담당·기한을 Markdown 회의록에 기록한다.
- 논문 작성 방향·제출처·일정은 지도교수님께 문의하여 정한다. 특정 월의 원고 완성을 현재 확정 일정으로 두지 않는다.

## 10. 기대효과·활용방안·예상 성과

의미 지도는 점군의 위치·색상에 객체 종류와 관측 근거를 더해 공간 정보를 해석하고 재사용할 수 있게 한다. 가상투어는 촬영 기록의 탐색을 돕고, 날짜별 변화 후보와 원본 근거는 사무실·교육시설 등의 물품 배치·적치물 점검을 보조한다. 모듈별 데이터 규격과 버전 관리를 통해 복원·분할 모델을 교체해도 후속 서비스와 연결할 수 있게 한다.

| 예상 성과 | 목표·조건 |
|---|---|
| 통합 SW | 의미 지도·가상투어·시계열 조회 웹 프로토타입 |
| 기술문서 | 실행 안내, 데이터·모듈·API 명세, 실험·한계·실패 사례 보고서 |
| 논문 | 1편 제출을 목표로 하되 주제·작성·제출 일정은 지도교수 협의 후 확정 |
| SW 등록 | 등록 범위와 주체를 협의하여 추진 검토 |
| 특허 | 선행기술 대비 차별성이 확보되면 출원 가능성 검토 |
| 앱 등록 | 웹 구현과 별개로 등록 대상·요건이 정해지면 검토 |

논문 제출과 채택·발표는 구분한다. 논문 작성을 이미 확정된 월별 작업이나 완료 성과로 표시하지 않는다. 코드·시연·평가 결과를 우선 확보하고 지도교수와 연구 기여 및 제출 계획을 구체화한다.
