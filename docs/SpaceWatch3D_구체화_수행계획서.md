# SpaceWatch3D 계획발표 및 수행계획서

> 수행 계획이며 구현 완료를 의미하지 않는다. 정기회의는 매주 화요일 주 1회 진행할 예정이며, 주요 학술 성과로 논문 제출을 추진한다. 세부 기술·담당자 배정·회의 시각은 팀 및 멘토 협의로 확정한다.
>
> 과제명: 3차원 가상투어 생성 자동화 기반의 시계열 공간 변화 모니터링 기술개발  
> 참여기업: ㈜뉴딕스 / 개발팀: SpaceWatch3D

## 계획발표 구성 요약

### 발표 1. 과제 목적 및 필요성

실내 360° 촬영 영상에서 위치·방향·이동 경로를 추정하고 대표 장면을 자동 연결하여 가상투어를 구성한다. 서로 다른 시점의 촬영을 공통 공간 좌표로 정합하여 변화 후보와 근거를 제공한다. 수작업 장면 연결, 반복 점검, 분산된 촬영 이력 관리를 줄이는 것이 목적이다.

### 발표 2. 과제 내용 및 추진방법

- **최종 목표:** 공간·촬영 날짜 선택, 360° 가상투어, 전후 비교, 객체 변화 표시와 이력 조회가 가능한 통합 웹 프로토타입 구현.
- **구현 흐름:** 기준 촬영 → 메타데이터·SLAM 지도 생성 → 키프레임·투어 구성 → 재촬영 → 기준 맵으로 3D 좌표 정합 → 공통 관측 영상 비교 → 변화 이력 표시.
- **비교 방식:** 기본안은 3D 공간 정합을 이용한 2D 영상·객체 변화 분석이다. 3D 점군·표면의 직접 비교는 별도 확장 연구로 구분한다. SLAM 수행만으로 3D 변화 분석이 완성되지는 않는다.
- **개발환경:** Linux 기반 영상 처리, GPU 사용 가능 환경, 웹 브라우저. 장비 사양과 버전은 초기 실험에서 결정.
- **기술스택:** Python/C++, OpenCV·NumPy, 360° 지원 SLAM, 특징점 매칭·RANSAC, PyTorch 기반 객체 탐지·분할, FastAPI, TypeScript/Three.js, SQLite 또는 PostgreSQL.
- **협업툴:** GitHub Issues로 태스크·실패 사례 관리, PR로 코드 검토, Projects로 일정 관리, Markdown으로 회의록·설계·실험 기록 공유.
- **병렬 개발:** N1 영상·위치, N2 키프레임·투어, N3 공간 정합, N4 변화 분석, N5 웹·이력 관리의 5개 노드로 분담.

| 요구사항 | 제공 기능 | 검증 방법 |
|---|---|---|
| 촬영 정보를 공간에 연결 | 프레임별 시간·자세·세션 메타데이터 | 원본·자세·시간의 대응과 추적 실패 구간 확인 |
| 가상투어 자동 생성 | 대표 장면 선택 및 이동 링크 생성 | 공간 커버리지·중복도·잘못된 링크 평가 |
| 재촬영의 동일 장소 대응 | 기준 맵 좌표계로 세션 정합 | 정답 대응쌍과 비교 및 실패율 측정 |
| 시간에 따른 상태 변화 확인 | 추가·제거·이동 후보, 비교 근거 표시 | F1·오탐률·영역 정확도 평가 |
| 운영 이력 관리 | 날짜·공간별 원본 및 결과 조회 | 업로드부터 비교 결과 조회까지 통합 시험 |
| 결과 신뢰성 | 비교 불가·판단 보류를 정상 무변화와 구분 | 가림·미촬영·정합 실패 사례 시험 |

### 발표 3. 추진 일정·담당자·회의

9월에 촬영·규격·위치 추정을 검증하고, 10월 중간발표까지 기본 투어와 초기 대응·변화 분석을 시연한다. 11월에는 통합·정량 실험·논문 초안을 진행하고, 12월에는 결과발표와 보고서·논문 제출 준비를 완료한다. 태스크별 담당 제안은 6절, 간트차트와 마일스톤은 9절에 명시한다.

정기회의는 **매주 화요일 주 1회**를 기본으로 한다. 팀원 전원 참여를 원칙으로 하며 멘토와의 주간 점검을 같은 회차에 포함하는 안으로 조율한다. 멘토 참석이 어려운 주에는 별도 시간을 조율하여 OT의 주 1회 이상 멘토 회의 요건을 충족한다. 회의 시각·방식은 확정 전이다.

### 발표 4. 기대효과 및 활용방안

대표 장면 선택·연결 자동화로 가상투어 제작의 반복 작업을 줄이고, 사무실·교육시설 등의 물품 배치와 적치물 변화를 원격 점검한다. 촬영 이력과 변화 근거를 연결하여 담당자가 결과를 직접 확인할 수 있게 한다. 상세 내용은 10절에 명시한다.

### 발표 5. 예상 성과

**주요 성과 목표는 논문 1편 제출**이다. 국내 학회 발표를 우선 경로로 삼아 키프레임 선별·공간 정합이 재촬영 대응 및 변화 탐지에 미치는 영향을 정량 검증한다. 제출처·마감은 9월 멘토·담당교수와 협의하며, 채택·발표는 심사 결과와 학회 일정에 따른다. 기술문서·소스코드·시연 영상을 함께 작성하고 SW저작권·특허·앱 등록은 추가 성과로 검토한다.

아래 본문은 발표에서 설명할 기능을 실행 순서와 입출력 수준으로 구체화한 상세 수행계획이다.

## 1. 과제 목적과 최종 목표

360° 카메라로 실내 공간을 반복 촬영하고, 각 촬영에서 위치·방향·이동 경로 등의 메타데이터를 생성한다. 대표 장면과 이동 가능한 연결을 이용해 가상투어를 자동 구성한다. 서로 다른 촬영의 공간 좌표를 기준 맵에 맞춘 뒤, 같은 구역이 보이는 과거·현재 장면에서 물체와 공간 상태의 변화를 분석한다.

최종 사용자는 웹에서 공간과 촬영 날짜를 선택하고, 가상투어 탐색·전후 영상 비교·변화 영역 및 이력 조회를 수행할 수 있다.

### 목적 및 필요성

- 영상의 어느 장면이 공간의 어디에 해당하는지 자동으로 연결하여 기록을 찾기 쉽게 한다.
- 대표 프레임 선택과 가상투어 이동 링크 작성에 필요한 반복 작업을 줄인다.
- 촬영 경로·위치·방향이 달라도 같은 구역을 찾아 비교할 수 있게 한다.
- 실제 변화와 촬영 조건 차이를 구별하여 수동 점검을 보조한다.
- 원본 영상, 촬영 위치, 비교 근거, 변화 결과를 함께 보관해 결과를 확인할 수 있게 한다.

## 2. 핵심 개념과 범위

### 2.1 촬영 횟수와 촬영 세션

촬영 세션은 대상 공간을 한 차례 기록한 묶음이다. 한 세션에 영상 파일이 여러 개 포함될 수도 있다. 프레임은 그 영상에서 추출한 이미지이며, 키프레임은 그중 목적에 맞게 선택한 대표 이미지다. 키프레임마다 별도 촬영을 하는 것은 아니다.

변화 비교에는 최소 두 시점의 촬영이 필요하다. 날짜가 같더라도 물체를 바꾸기 전과 후에 촬영했다면 서로 다른 비교 시점이 된다.

| 예시 세션 | 촬영 내용 | 목적 |
|---|---|---|
| A: 기준 촬영 | 방 A → 복도 → 방 B를 이동하며 촬영 | 기준 상태와 기준 맵 생성 |
| B: 재촬영 | 이후 같은 공간을 촬영. 반대 순서로 이동해도 됨 | A와 공간을 대응시켜 상태 변화 비교 |
| C 이후 | 필요 주기에 따라 재촬영 | A 대비 누적 변화 또는 직전 세션 대비 변화 조회 |

실험에서는 두 번의 촬영만으로 성능을 결론내리지 않고, 변화 없음·실제 변화·촬영 조건만 변화한 세션을 추가 확보한다.

### 2.2 혼동하기 쉬운 용어

| 용어 | 이 계획에서의 구체적 의미 | 구분할 개념 |
|---|---|---|
| 시간 동기화 | 한 촬영 안에서 영상·IMU 등의 측정 시간을 맞추는 일 | 서로 다른 날짜를 같은 날짜로 바꾸는 일이 아님 |
| 프레임 순서·자세 정리 | 한 세션의 프레임을 시간 순으로 관리하고 카메라 위치·방향을 연결하는 일 | 이미지 픽셀을 모두 겹치는 일이 아님 |
| 중복 프레임 제외 | 같은 위치·유사한 관측으로 추가 정보가 적은 프레임을 특정 용도의 후보에서 제외 | 같은 방의 모든 프레임을 하나로 만드는 일이 아님 |
| 키프레임 선별 | 대표 장면을 고르는 일 | 화면의 이동 화살표를 만드는 일과 구분 |
| 투어 그래프 생성 | 대표 장면 간 이동 가능한 연결을 만드는 일 | 촬영 세션 간 좌표계를 맞추는 일과 구분 |
| 세션 간 공간 정합 | 서로 다른 촬영의 같은 실제 장소가 같은 좌표에 놓이도록 변환을 추정 | 촬영자가 걸은 경로를 동일하게 만드는 일이 아님 |
| 비교 영상 정렬 | 대응 장면에서 방향·투영·시점 차이를 고려해 비교 가능한 영역을 맞추는 일 | 공간 좌표계 정합만으로 자동 완료되지 않음 |
| 시계열 변화 분석 | 서로 다른 촬영 시점의 같은 구역에서 상태가 어떻게 바뀌었는지 분석 | 같은 세션 안의 중복 제거와 구분 |

### 2.3 기본 지도 표현과 확장 범위

기본 구현안은 **희소 3D 지도 + 카메라 자세 + 원본 파노라마 + 투어 그래프**다. 희소 지도는 위치 추정·장소 대응에 사용하고, 파노라마는 실제 촬영 상태의 확인과 화면 표시에 사용한다. 희소 특징점만으로 벽·가구 표면이 채워진 3D 모델이 완성되는 것은 아니다.

메시 또는 3D Gaussian Splatting 복원은 자유 시점 탐색·표면 분석·시점 보정 비교가 요구될 때 검증할 확장 기능으로 둔다. 기업이 기대하는 ‘3차원 가상투어’의 결과물 형태는 초기 요구분석에서 확인한다. 카메라가 360°라는 이유만으로 결과물을 메시나 3DGS로 확정하지 않는다.

### 2.4 3D 공간 정합과 3D 변화 탐지의 구분

현재 기본안은 **3D에서 위치를 대응시키고, 대응된 2D 관측에서 상태 변화를 판정하는 방식**이다. 다음 세 처리를 구별한다.

| 처리 | 비교·추정 대상 | 기본안 포함 여부 |
|---|---|---|
| 3D 공간 정합 | 두 세션의 지도점·카메라 자세·기하 대응 | 포함 |
| 2D 관측 기반 변화 분석 | 공통 구역의 전후 영상, 객체·영역·특징 | 포함 |
| 3D 공간의 직접 변화 분석 | 정합된 점군·표면·점유 공간·3D 객체 | 별도 확장 연구 |

예를 들어 의자 추가를 기본안에서는 대응 영상의 객체 관측으로 검출한다. 3D 직접 비교에서는 이전에 관측된 빈 공간에 새 표면 또는 객체가 생겼는지 확인한다. 이를 위해서는 충분한 깊이·다중시점 복원, 스케일·좌표 정합, 관측 가능성 및 불확실성 처리가 추가로 필요하다.

일반적인 희소 SLAM 지도는 벽·의자 표면을 빠짐없이 표현하지 않는다. 추출된 특징점 개수나 위치의 차이만으로 객체 추가·제거를 확정할 수 없다. 또한 3DGS를 현재 시점으로 렌더링한 뒤 사진과 비교하는 방식도 변화 판정 자체는 영상 공간에서 수행될 수 있다.

따라서 기본안의 명칭은 ‘3D 공간 정합 기반 시계열 영상 변화 분석’으로 명확히 사용한다. 직접 3D 비교를 목표로 확정하면 N1/N3의 출력에 복원 기하와 관측 정보를 추가하고, N4의 입력·알고리즘·평가 지표 및 일정을 함께 변경한다.

## 3. 전체 실행 흐름

```text
[첫 촬영 A]
1. 원본 영상·촬영 정보 저장
2. 프레임 추출 및 품질 정보 생성
3. SLAM으로 A의 카메라 자세·희소 지도·공간 메타데이터 생성
4. A의 투어용 키프레임 선별
5. 이동 가능한 연결을 구성하여 A의 가상투어 생성
6. 검증된 A의 지도 버전을 기준 좌표계로 지정

[이후 촬영 B]
7. B의 원본·프레임·카메라 자세·메타데이터 생성
8. A와 B의 동일 장소를 검증하고 B의 좌표를 기준 맵에 정합
9. 공통 구역이 보이는 A/B 장면을 선택하고 비교 가능 영역 생성
10. 서로 다른 촬영 시점의 객체·공간 상태 변화 분석
11. 웹에서 전후 영상·변화 영역·촬영 및 분석 이력 조회
```

가상투어 화면 완성은 변화 분석의 선행 조건이 아니다. 비교쌍이 확보되면 변화 분석과 웹 개발은 별도로 진행할 수 있다. B의 키프레임·투어도 세션별로 생성하여 날짜 선택 시 제공한다.

## 4. 단계별 구체적 수행방법

### 1단계. 기준 공간 촬영 및 원본 저장

- **입력:** 360° 카메라, 촬영 대상 공간, 촬영 시각, 확보 가능한 카메라·IMU 정보.
- **처리:** 방·복도 사이를 이동하며 겹치는 관측을 확보하고, 영상과 세션 ID를 저장한다.
- **출력:** 원본 파일, 세션 목록, 촬영 시각, 카메라 모델·투영 방식·해상도, IMU 제공 여부.
- **완료 기준:** 모든 원본이 세션에 연결되고 다시 읽을 수 있다.

위치·방향이 카메라에서 모두 제공된다고 가정하지 않는다. 촬영 시 바로 얻는 시간·기기 정보와, 이후 SLAM으로 추정하는 위치·방향을 구분해 저장한다. 제자리 회전만으로 공간 전체를 충분히 복원했다고 판단하지 않는다.

### 2단계. 프레임 추출 및 품질 관리

- **입력:** 원본 영상과 촬영 정보.
- **처리:** 프레임 ID와 영상 내 시간을 연결하고 선명도·노출·유사도 등 품질 정보를 계산한다. 선택한 알고리즘의 입력에 맞게 원본 파노라마 또는 변환 이미지를 준비한다.
- **출력:** 프레임 목록, 품질 점수, 원본과 파생 이미지의 대응 정보.
- **완료 기준:** 각 프레임이 어떤 영상의 어느 시점인지 추적 가능하다.

멈춘 상태로 거의 같은 모습이 반복되면 투어용 중복 후보로 표시한다. 같은 방의 입구와 창가처럼 관측 위치와 가려짐이 다르면 별도 장면으로 유지할 수 있다. 원본을 삭제하는 대신 사용 목적별 선택 목록을 저장한다. SLAM용 입력은 추적 연속성을 고려하여 별도로 유지한다.

### 3단계. 한 촬영 내부의 위치 추정과 지도 생성

- **입력:** 시간 순 영상 프레임, 카메라 모델, 사용 가능한 경우 동기화된 IMU.
- **처리:** 연속 관측의 특징을 추적해 카메라 위치·방향과 희소 3D 특징점을 추정한다. 재방문 관측을 활용해 경로 오차를 보정한다.
- **출력:** 세션 내부 좌표계의 카메라 자세, 지도, 특징 정보, 추적 상태, 메타데이터.
- **완료 기준:** 시험 경로의 추적 성공 구간과 실패 구간을 구분할 수 있고 영상·자세가 연결된다.

이 단계는 한 촬영 안의 관측들을 공간적으로 연결하는 과정이다. 세션 B를 별도로 처리하면 B의 원점·방향·스케일은 A와 다를 수 있다. 단안 방식에서 실제 길이 기준이 확보되지 않았다면 좌표 단위를 미터로 단정하지 않는다.

### 4단계. 대표 키프레임 자동 선별

- **입력:** 프레임, 카메라 자세, 품질 점수, 관측 중첩 정보.
- **처리:** 위치 변화, 새롭게 관측되는 영역, 선명도, 중복 정도, 주요 구역 커버리지를 고려해 투어용 장면을 선택한다.
- **출력:** 투어용 키프레임 목록과 선택 근거.
- **완료 기준:** 대표 장면 수를 줄이면서 지정 주요 구역을 빠뜨리지 않는다.

360° 파노라마에서는 제자리 회전만으로 새로운 영역이 크게 늘지 않을 수 있다. 따라서 회전량 하나만으로 키프레임을 추가하지 않는다. ‘화살표를 눌러 이동’하는 기능은 다음 단계에서 만든다. SLAM용 키프레임, 투어용 키프레임, 비교용 후보 프레임을 용도별로 구분한다.

### 5단계. 공간 연결 관계와 가상투어 구성

- **입력:** 투어용 키프레임, 위치·방향, 촬영 경로와 관측 관계.
- **처리:** 대표 장면을 투어 노드로 만들고 이동 가능한 노드 사이에 링크를 구성한다. 링크 방향을 파노라마 뷰어의 화살표와 연결한다.
- **출력:** 투어 그래프, 파노라마 경로, 이동 링크 및 화면 표시용 방향.
- **완료 기준:** 입구 → 복도 → 회의실과 같은 실제 이동 관계를 따라 탐색할 수 있다.

단순히 공간상 가까운 노드라는 이유만으로 벽 너머 방에 링크를 만들지 않는다. 촬영 경로와 기하·관측 근거가 있는 연결을 우선 사용하고, 불확실한 연결은 보류한다. 초기에는 사람이 검증한 구역 이름을 사용할 수 있으며 자동 방 분류를 선행 필수 조건으로 두지 않는다.

### 6단계. 기준 맵 지정

- **입력:** 검증된 A의 지도와 카메라 자세.
- **처리:** 이후 비교가 참조할 기준 맵 ID·버전·좌표계·스케일 상태를 지정한다.
- **출력:** 기준 맵 스냅샷 및 참조 메타데이터.
- **완료 기준:** 이후 촬영 결과가 어떤 지도 버전을 기준으로 정합됐는지 추적할 수 있다.

고정하는 것은 공간 좌표의 기준이다. 물체 상태를 기준 시점과 같게 강제로 맞추는 것이 아니다. 기준 맵이나 최적화 결과를 수정해야 한다면 새 버전을 만들고 기존 비교 이력이 참조하는 버전을 유지한다.

### 7단계. 같은 공간 재촬영 및 별도 기록

- **입력:** 이후 시점의 촬영 영상 B.
- **처리:** 1~4단계의 데이터 처리로 B의 원본·자세·메타데이터를 생성한다.
- **출력:** A와 별도 세션 ID를 갖는 B의 기록과 지도.
- **완료 기준:** 촬영 날짜와 원본 상태를 보존한 채 두 세션을 독립 조회할 수 있다.

촬영 순서와 경로가 A와 완전히 같을 필요는 없다. 다만 실제 비교할 구역이 양쪽 촬영에 관측되어야 한다. B에서 촬영하지 않은 구역은 ‘변화 없음’으로 처리하지 않는다.

### 8단계. 세션 간 공간 정합

- **입력:** 기준 맵 A, B의 지도·자세, 각 세션의 후보 이미지와 특징 정보.
- **처리:** 동일 장소 후보 검색 → 특징 대응 → 기하 검증 및 오매칭 제거 → 기준 좌표계 변환 추정 순서로 수행한다.
- **출력:** B에서 A로의 좌표 변환, 공통 좌표계의 카메라 자세, 대응 근거, 정합 상태.
- **완료 기준:** 두 촬영의 같은 문·벽·복도가 기준 좌표계에서 일관되게 대응된다. 반대 방향으로 걸은 경우도 평가한다.

Metric scale이 확보되면 SE(3), 상대 스케일까지 맞춰야 하면 Sim(3) 변환을 검토한다. Sim(3) 예시는 다음과 같다.

```text
X_A = s * R * X_B + t
X_B: B 지도상의 점 / X_A: A 기준 좌표로 변환된 점
R: 회전 / t: 이동 / s: 상대 스케일
```

이미지의 2D 매칭만으로 지도 간 3D 변환이 바로 정해지는 것은 아니다. 대응되는 지도점 또는 카메라-지도 관계를 이용해 변환을 추정하고 여러 관측으로 검증한다. ICP는 충분한 중첩과 적절한 초기 정합·점군이 있을 때 추가 보정으로 검토한다.

**경로를 동일하게 만드는 것이 아니다.** A가 입구 → 복도 → 회의실, B가 회의실 → 복도 → 입구 순서여도 각 실제 장소가 같은 위치에 놓이면 된다. **날짜 정보는 그대로 보존한다.** 이동한 의자에 맞춰 배경 지도를 왜곡하지 않도록 안정적인 구조의 일관된 대응을 우선한다.

대안으로 B의 위치를 처음부터 A의 기존 지도에서 추정할 수 있다. 이 경우 독립 지도 두 개의 사후 정합 과정은 줄어들지만, 기존 지도에서의 위치 추정 성공 여부를 검증해야 한다. 초기 구현에서 두 경로를 모두 필수로 개발하지 않고 장비·데이터 실험으로 선택한다.

### 9단계. 비교할 전후 장면과 유효 영역 결정

- **입력:** 공통 좌표계의 A/B 자세, 원본 이미지, 정합 결과.
- **처리:** 같은 구역이 공통으로 보이는 프레임을 선택한다. 방향·투영을 맞추고 시차·가림·화질을 고려해 비교 가능한 영역을 결정한다.
- **출력:** 전후 이미지 쌍, 유효 영역, 사용한 시점·구역, 비교 가능 여부 및 사유.
- **완료 기준:** 다른 방이나 반대쪽 벽을 비교하지 않고, 공통 관측 범위를 확인할 수 있다.

공간 좌표가 맞아도 영상 픽셀은 자동으로 일치하지 않는다. 카메라의 평행 이동으로 생기는 시차는 단순 회전이나 하나의 2D 변환으로 모두 제거되지 않을 수 있다. 초기에는 충분히 유사한 관측 위치의 비교쌍을 우선하고, 정렬이 불확실한 영역은 제외한다. 3DGS 렌더링을 도입할 경우에도 렌더링 오류와 미관측 영역을 별도로 검증한다.

### 10단계. 시계열 공간 변화 및 이벤트 분석

- **입력:** 서로 다른 시점의 비교쌍과 유효 영역.
- **처리:** 차영상·SSIM 등 기준선과 객체 탐지·분할·특징 비교를 평가해 실제 상태 변화 후보를 찾는다.
- **출력:** 변화 영역, 추가·제거·이동 후보, 신뢰 정보, 근거 이미지, 분석 상태.
- **완료 기준:** 실제 변화 사례와 변화 없이 조명·시점만 달라진 사례를 구분해 정량 평가한다.

예: A의 회의실에는 없던 상자가 B의 같은 관측 구역에 확인되면 ‘상자 추가’ 후보를 기록한다. 단순히 B에서 객체가 검출되지 않았다는 이유만으로 제거를 확정하지 않는다. 가림·촬영 누락·탐지 실패를 함께 검토한다.

이동 판정은 같은 객체라는 대응 근거가 필요하다. 이미지상 위치 변화만으로 실제 물체 이동을 단정하지 않으며, 서로 비슷한 의자처럼 개체 구분이 어려우면 ‘재배치 후보’ 또는 ‘판단 보류’로 남긴다. 정확한 cm 단위 이동량은 기본 목표에 포함하지 않는다.

관심 이벤트는 우선 ‘통로 구역에 새 적치물 발생’처럼 대상 구역·객체·판정 규칙을 정의해 구현한다. 촬영 사이에 실제로 언제 사건이 발생했는지는 알 수 없으므로 변화 발생 구간을 A 촬영 이후~B 촬영 이전으로 기록한다. VLM 설명 생성은 탐지 근거를 보완하는 선택 기능으로 검토한다.

### 11단계. 웹 표시 및 시계열 이력 관리

- **입력:** 세션별 투어, 비교쌍, 변화 결과, 각 처리 단계의 상태.
- **처리:** 공간·촬영 날짜·비교 기준을 선택하고 전후 화면, 변화 표시, 이벤트 목록을 제공한다.
- **출력:** 통합 웹 서비스와 공간별 촬영·분석 이력.
- **완료 기준:** 사용자가 변화 결과에서 해당 원본과 비교 근거로 이동할 수 있다.

변화가 없는 결과와 비교하지 못한 결과를 구분한다. 초기 변화 마커는 해당 촬영 노드와 이미지 영역에 연결한다. 깊이·기하 근거가 없는 2D 탐지 결과를 정확한 3D 객체 위치로 표시하지 않는다.

## 5. 데이터 규격과 실패 처리

| 데이터 단위 | 필수 정보 |
|---|---|
| 공간·세션 | scene_id, session_id, 촬영 시각 및 시간대, 원본 경로, camera_id |
| 프레임 | frame_id, session_id, 영상 내 시간, 이미지 경로, 투영 방식, 해상도 |
| 자세·지도 | map_id, map_version, 프레임별 위치·방향, 좌표축·변환 방향, 스케일 상태, 추적 상태 |
| 키프레임·투어 | 사용 목적, 선택 프레임, 선택 이유, 노드·이동 링크 |
| 정합 | 기준·대상 세션 및 지도 버전, 대상→기준 변환, 검증 근거, 성공·실패 상태 |
| 비교쌍 | 이전·이후 프레임 ID, 유효 영역, 비교 가능 여부·사유 |
| 변화 | 비교쌍 ID, 유형, 이미지상 영역, 객체 대응 근거, 분석 버전, 신뢰 정보 |

초기 연결은 JSON 메타데이터와 영상·이미지·지도 파일을 사용한다. 대용량 파일을 JSON에 직접 담지 않는다. 카메라 자세의 행렬 방향, 좌표축, 파노라마 방향과 뷰어 방향의 관계를 공통 규격으로 고정한다. 실제 길이 스케일이 확보된 경우에만 미터 단위를 사용한다.

실패 상태는 최소한 `추적 실패`, `정합 실패`, `공통 관측 부족`, `변화 판단 보류`로 구분한다. 실패한 구간의 비율을 평가에서 공개하고, 이를 정상 비교의 ‘변화 없음’에 포함하지 않는다.

## 6. 5인 노드별 병렬 개발 계획

노드는 독립 실행 가능한 모듈을 뜻하며, ROS 사용을 전제하지 않는다. 아래 실명 배정은 기존 발표 초안에서 제시한 **제안안이며 확정 배정이 아니다.**

| 담당 제안 | 책임 노드 | 입출력 | 다른 노드를 기다리지 않는 개발 방법 |
|---|---|---|---|
| 서관우 | N1 영상·위치·메타데이터 | 원본 → 프레임·자세·지도·품질 정보 | 샘플 영상과 카메라 정보로 추적·저장 시험 |
| 이태훈 | N2 키프레임·투어 그래프 | 프레임·자세 → 대표 장면·이동 링크 | 제공된 자세 JSON 또는 수작업 테스트 데이터 사용 |
| 임현우 | N3 세션 정합·비교쌍 | 두 세션의 지도·이미지 → 변환·비교쌍·유효 영역 | 사전 생성한 지도와 정답 대응쌍 사용 |
| 시한결 | N4 변화·이벤트 분석 | 전후 이미지·유효 영역 → 변화 영역·유형·근거 | 사람이 대응시킨 전후 이미지와 정답 마스크 사용 |
| 김동주 | N5 웹·운영 이력 | 각 노드 결과 → 저장·조회·시각화·작업 상태 | 샘플 투어 그래프와 변화 JSON으로 화면·API 개발 |

N1은 카메라 자세·품질 정보를 제공하고 N2는 최종 투어용 선택을 책임진다. N3는 공간 대응 및 비교 준비를, N4는 준비된 비교쌍의 변화 판정을 책임진다. N2는 투어 그래프를 만들고 N5는 실제 이동 UI를 구현한다.

첫 주에 샘플 입력·출력과 규격을 공유하고, 초기에는 샘플 결과로라도 전체 연결을 확인한다. 각 담당자는 자기 노드의 코드·시험·설계문서·발표 슬라이드를 작성한다. 발표자료 취합은 회차별로 정하며 실제 발표는 모든 팀원이 번갈아 참여한다.

## 7. 개발환경·기술 선택 계획

| 분야 | 후보 및 선택 기준 |
|---|---|
| 환경 | Linux 기반 비전 처리 환경, GPU 사용 가능 환경, 웹 브라우저 |
| 언어·영상 처리 | Python/C++, OpenCV, NumPy |
| 360° 위치 추정 | stella_vslam/OpenVSLAM 계열의 구면 입력 지원 검토. ORB-SLAM3는 지원 카메라 모델 및 입력 변환 검증 후 후보로 비교 |
| 오프라인 재구성 | COLMAP 등은 파노라마 또는 가상 카메라 입력 구성이 검증된 경우 초기 비교 후보로 사용 |
| 특징 대응·정합 | ORB/SIFT 또는 SuperPoint·LightGlue, RANSAC, Open3D |
| 변화 분석 | PyTorch, 객체 탐지·분할 사전학습 모델, 영상 차이 기준선 |
| 서비스 | FastAPI, JavaScript/TypeScript, Three.js/WebGL 또는 파노라마 뷰어 |
| 저장 | 초기 SQLite 및 파일 저장, 필요 시 PostgreSQL |
| 협업 | GitHub Issues·PR·Projects, Markdown 회의록·설계문서 |

360° 입력을 지원하는 SLAM을 우선 시험한다. Cubemap 변환이나 IMU 존재만으로 호환성과 정확도가 보장된다고 가정하지 않는다. IMU 연동에는 해당 구현의 지원 여부와 영상 동기화가 필요하다. 구체적인 모델 버전·처리 해상도·프레임 간격은 실제 장비 데이터로 결정한다.

## 8. 검증 계획과 우선순위

### 최우선 검증

**변화가 없는 같은 공간을 다른 경로로 다시 촬영했을 때, 같은 구역을 정확하게 찾아 비교할 수 있는가?**

먼저 방 두 곳과 연결 복도의 반복 촬영으로 N1·N3의 대응 성능을 확인한다. 이후 같은 공간의 물체를 추가·제거하고 N4를 연결한다. 고품질 3D 렌더링보다 반복 촬영 대응과 실제 변화 구분을 우선한다.

| 시험 조건 | 기대 결과 |
|---|---|
| 변화 없음, 비슷한 경로 | 정상 대응 및 불필요한 변화 표시 억제 |
| 변화 없음, 반대 경로·다른 방향 | 경로가 달라도 동일 장소 대응 |
| 조명만 변경 | 객체 추가·제거로 오판하지 않음 |
| 객체 추가·제거 | 유효 관측 영역에서 변화 후보 검출 |
| 객체 이동 | 동일 객체 대응이 확인된 경우 이동 판정 |
| 일부 공간 미촬영·가림 | 비교 불가·판단 보류 처리 |
| 비슷하게 생긴 다른 방 | 외형 유사도만으로 오정합하지 않음 |

평가 지표는 추적 성공률, 비교쌍 대응 정확도, 대응 가능 범위, 투어 커버리지, 변화 정밀도·재현율·F1, 무변화 비교쌍의 오탐률, 처리 시간으로 정한다. 정밀한 위치 오차를 보고하려면 별도 위치 정답이 필요하다.

수치 목표와 임계값은 초기 데이터 및 멘토 요구를 확인한 뒤 확정한다. 성공 사례만 선택하지 않고 정합 실패와 비교 불가능 비율을 함께 보고한다.

연구 후보는 ‘동일 프레임 예산에서 키프레임 선별 방식이 장면 대응과 변화 탐지에 미치는 영향’으로 제안한다. 일정 시간 간격, 위치 기반, 품질·중첩·커버리지 기반 선별을 동일 조건으로 비교한다. 신규성은 추가 선행연구 검토로 확인한다.

## 10. 기대효과·활용방안·예상 성과

- **시설 기록:** 사무실·교육시설 등의 촬영 기록을 공간·날짜별로 탐색한다.
- **가상투어 제작:** 대표 장면 선별과 이동 링크 구성의 수작업을 줄인다.
- **원격 점검:** 가구 배치·물품 추가·적치물 등 변화 후보를 전후 영상으로 확인한다.
- **운영 이력:** 촬영 시점과 분석 근거를 연결해 변경 사항을 추적한다.
- **확장성:** 위치 추정·키프레임·정합·분석·웹 모듈을 독립적으로 개선한다.

최종 개발 산출물은 통합 웹 프로토타입, 노드별 코드, 실행 안내, 메타데이터 명세, 실험 데이터의 공개 가능한 부분, 성능 평가서와 시연 영상이다.

### 주요 학술 성과: 논문 1편 제출

논문 제출을 주요 성과로 계획하고, 국내 학회 발표를 우선 추진 경로로 삼는다. 후보 제목은 **‘공간 컨텍스트 기반 키프레임 선별과 세션 정합을 활용한 실내 시계열 변화 모니터링’**이다. 구체적인 기여와 제목은 선행연구 및 초기 실험으로 확정한다.

| 시기 | 논문 수행 내용 | 산출물 |
|---|---|---|
| 9월 | 선행연구·제출처 조사, 멘토·교수와 연구 질문 및 마감 협의 | 관련 연구표, 제출 일정, 실험 설계 |
| 10월 | 동일 프레임 예산의 비교군 구현, 정답 데이터 확보, 초기 평가 | 재현 가능한 기준선, 평가 코드·데이터 규격 |
| 11월 | 키프레임 기준 및 정합 적용 전후 비교, 실패·가림·조명 조건 분석 | 결과 표·그림, 한계 분석, 논문 초안 |
| 12월 | 추가 검증, 멘토·교수 검토, 원고·발표자료 정리 | 제출 원고, 제출 증빙, 발표자료 |

실제 제출일은 선택한 학회의 마감에 맞추고, 학기 내 발표가 필요하면 9월에 역산하여 원고 일정을 앞당긴다. 논문 제출과 채택·발표를 구분하며 채택을 보장하지 않는다. OT에서 요구하는 ‘국내 학회 논문 발표’ 실적은 제출만으로 충족한 것으로 표시하지 않는다. 학회 일정이 맞지 않을 경우 별도 인정 실적의 확보 방안을 멘토와 사전에 조율한다.

논문 제출 전 담당교수의 검토를 받고, OT의 저자 구성·SW중심대학 사사 요건을 확인하여 반영한다. 팀원은 담당 노드의 방법·실험 내용을 작성하고 원고 취합 담당은 팀 회의에서 정한다.
