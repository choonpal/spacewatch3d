# SpaceWatch 논문 구현 통합본

이 묶음은 결과 사진이나 예전 선정 결과를 재생하는 묶음이 아니라 실행 소스이다.
설문 응답·설문 분석 코드는 포함하지 않는다. 계산 실행은 `execution06/run`에서
뷰어까지 완료했다. 배포 범위는 상위 `RELEASE.json`, 실제 계산 상태는
`evidence/calculation_status.json`을 따르며, 원본부터의 전체 재복원 검증과 구분한다.

## 실행 경로

`원본 영상 → 원래 전처리/OOOPS/PanoVGGT/Poisson/의미 투표 → 통계적 객체 영역 →
전체 영상 선명도 → 0.25초 구간별 최대 선명도 후보 → 새 가시성·객체 품질 행렬 →
관측점 선정 → 원본 ERP 추출 → 새 회차 정합 → 원본 RGB SimSaC → 통합 뷰어`

고정 모델 가중치와 실행 환경은 학교 서버에 이미 설치된 것을 사용한다.
프로그램은 모델·패키지를 자동으로 내려받거나 설치하지 않는다.

### 검증된 상류 자료에서 이어 실행

```bash
cd /workspace/spacewatch_integrated_20261110_8QJn4J/final_release_v1/code
python3 spacewatch.py doctor --config configs/dorm45-paper.json
python3 spacewatch.py start --config configs/dorm45-paper.json --output ../runs/new_run
python3 spacewatch.py status --output ../runs/new_run
```

이 설정은 점군·카메라·의미 메시·2D 라벨을 해시 확인 후 명시적으로 재사용한다.
후보·관측 행렬·선정·정합·변화 추론·뷰어는 새로 실행한다. 예전 최종 키프레임이나
변화 판단 결과를 가져오지 않는다. 같은 소스/설정으로 중단된 실행은 같은 명령과
출력 경로로 재개할 수 있다. 소스나 설정을 바꾸면 새 출력 경로가 필요하다.

### 원래 생성기부터 실행

```bash
python3 spacewatch.py run-fresh --request requests/dorm45-fresh.json --output ../runs/new_raw_run
```

`run-fresh`는 원래 영상 준비 생성기와 원래 OOOPS/PanoVGGT/메시/의미 투표 및
통계 프로필을 실행하고, 실제 생성된 경로를 현재 통합 실행기에 넘긴다.
새 전처리 결과에 예전 키프레임·변화 결과를 섞지 않는다. 해당 생성기가 요구하는
촬영 입력·고정 모델·좌표/프로필 문맥은 요청 파일에 출처와 해시로 명시한다.
자동으로 알 수 없는 축척이나 촬영자 마스크를 추측해서 성공으로 처리하지 않는다.
원래 생성기의 복원용 기본 프레임 간격과 1036×518 입력은 유지하며, 이것과
전체 영상에서 0.25초 구간별로 고르는 관측 후보는 별개이다. 사람 마스크는
원래 OOOPS·시간 이웃 합집합·촬영자 고정 영역·팽창·나디르 정책을 사용한다.
19개 클래스 입력에서 사람 번호가 바뀌므로 번호 대신 클래스명으로 연결한다.

현재 서버 여유 메모리에서 대형 재복원을 무리하게 시작하지 않도록 보호한다.
점군 생성/메시 재계산의 기본 최소 가용 메모리는 16 GiB이며, 부족하면 시작 전에
중단한다. CPU 최대 4스레드, 큰 단계 순차 실행, GPU 협력 잠금과 유한 마감을 쓴다.
GPU 여유가 없다고 다른 사용자의 작업을 중단하지 않는다.
변화 추론과 객체 대응 특징 추출은 별도 프로세스로 순차 실행하여 모델 메모리가 겹치지 않게 한다.

## 논문과 연결되는 구현

| 부분 | 구현 기준 |
|---|---|
| 전처리·복원·메시·의미 투표 | 실제 Dorm4/5 원래 생성기와 5.1.9 원본 소스. Gaussian 학습·합성 및 가상 탐욕 경로는 실행하지 않음 |
| 후보 | 모든 원본 프레임의 선명도를 측정하고 각 0.25초 구간에서 최대값 선택. 앞단 품질 탈락 없음 |
| 공간 | 면적 비례 표면 표본점, 광선 가시성, 중복 1회, 3×3 복원 단위 구역 균형 |
| 객체 | 같은 의미 클래스의 연결 영역. 가림 비율 × `min(1,입체각/0.02 sr)` |
| 중요도 | 매뉴얼·객체 종류에 대한 저장된 1–5점 5회 응답 검증·평균·정규화. 현재 객체 ID에 종류로 연결. 새 API 호출 없음 |
| 선정 | 새 관측 행렬의 다중 시작점 탐욕 추가·국소 교체. 교체 후 공간 2%와 객체 3% 추가 이득 조건. 안전 장수 상한은 목표 장수 아님 |
| 정합·변화 | 새 벽/바닥 구조 정합 및 지역 보정, 현재 키프레임 주변 실제 영상, 전체 ERP+6방향+객체 확대 SimSaC, 국소/전역 평균, 일반적 묶음 처리 |
| 뷰어 | 최신 WASD/지도 이동/전환 UI, 현재 선정 ID와 실제 ERP, After 회차의 현재 변화 결과. 비교 사진과 다른 프레임에 박스를 임의로 붙이지 않음 |

객체 품질 원식과 원래 통계 노이즈 정책은 유지한다. 통계 제외는 독립적인 객체
관측 의무에서의 제외이며, 정상 메시를 삭제하는 처리가 아니다.
촬영 경로의 XYZ와 시간순 왕복을 사용하며, 보간 자세는 독립 정확도 미검증으로 남긴다.

## 구성과 저장 범위

- `code/spacewatch.py`: 실행 진입점
- `code/spacewatch_pipeline/`: 단계 실행기 및 좁은 통합 어댑터
- `code/apps/autotour360/`: 현재 통합 뷰어
- `code/tools/mesh_simsac/`: 채택된 최종 RGB 변화 소스
- `inputs/`: 필요한 중요도 캐시와 소규모 의미 메시/프로필 입력
- `evidence/`: 출처·해시·논문 로직 대조·시험·실제 실행 기록
- `execution*/`: 수정 전 실패와 소스 동결 실측 실행. 과거 실행은 덮어쓰지 않음

대형 원본 영상, 점군/중간 복원 배열, 전체 2D 라벨 캐시 및 모델은 서버의 원래
입력 경로를 유지한다. 소스 배포 파일에 거대 모델·영상·점군을 불필요하게 복제하지
않는다. 따라서 다른 컴퓨터에서는 런타임과 데이터 경로를 설치/연결하고 doctor를
통과해야 실행할 수 있으며, 작은 소스 압축파일만으로 모델까지 독립 실행된다고
주장하지 않는다.

## 해석상 주의

- 연결 실행은 `execution06/run`에서 뷰어까지 완료했고, Dorm5 혼합 선정 10개는 논문의
  최종 선정과 같다. 과거 15지점 기반 변화 효과 평가와 현재 10지점 기반 통합 실행은
  비교 입력이 다르다. 과거 6후보·3묶음과 현재 5후보·2묶음의 차이만으로 구현이 논문과
  다르다고 판단하지 않는다. 현재 상자 변화의 반복 근거 부족은 검출 결과의 한계로 남기며,
  알려진 프레임이나 옛 검출을 추가해 과거 평가 개수를 맞추지 않는다.
- 좌표는 논문과 같이 복원 단위 `u`이다. 2.7m 천장 가정은 실제 축척 검증이 아니다.
- 실행 완료·파일 계약 통과는 모든 객체 관측, 정합 정확성, 변화 정답률의 보증이 아니다.
  `targets_unmet`, `UNVERIFIED`, `underconstrained` 등을 숨기거나 성공으로 바꾸지 않는다.
- 저장된 LLM 요청 ID는 `gemini-3.1-flash-lite`이며 기존 동일 매뉴얼의 5회 점수 캐시를 쓴다.
  논문의 축약 표기만으로 모델 교체나 알고리즘 차이를 판단하지 않는다.
- RGB 비교는 촬영자 마스크만 적용하고 일반 사람의 의미 라벨을 유지한다. 작은 객체 확대
  목록에서 사람이 빠지는 것은 원래 채택한 코드도 동일하며, 일반 사람은 별도 RGB-person
  변화 분기로 탐지한다. 객체 확대 자격과 전체 사람 탐지를 혼동하지 않는다.
- 현재 자료에 맞춘 과거 변화 개발 과정이 있었으므로 독립 정답 미사용 검증으로
  확대 해석하지 않는다. 이 통합 작업은 새로운 정답 ID·좌표 예외를 추가하지 않는다.

## 시험

```bash
python3 run_tests.py
```

서로 다른 기존 런타임에 필요한 라이브러리를 가진 환경에서 원래 시험을 나눠
실행한다. 시험을 통과시키기 위해 원래 코어 시험이나 과학적 문턱을 완화하지 않는다.
단위 시험과 실제 통과 실행의 결과는 따로 기록한다.
